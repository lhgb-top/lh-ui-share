El calendario es un **panel de fechas permanente**: date-picker esconde el panel en una capa emergente; calendar lo despliega en la página. Admite tres modos de selección — única, intervalo, múltiple — y la restricción por un rango de fechas seleccionables. `core/calendar` reutiliza el algoritmo de la cuadrícula de date-picker (`generateCalendarDays`) y, por encima, añade desplazamiento, restricción de rango y conmutación del estado de selección.

## Cuándo usarlo

- Cada framework implementa `LhCalendar`: vistas de agenda, registros de asistencia, páginas de selección de fechas de hotel o vuelos.
- Escenarios en los que la fecha debe estar **permanentemente visible** y noelegida en una capa emergente.
- **No usarlo para**: dentro de formularios con espacio limitado (usa `date-picker`, la capa emergente ocupa menos); cuando solo se elige una fecha y la página ya está saturada.

## Intención de diseño

**La dirección de la dependencia es semántica**: calendar importa `generateCalendarDays` de `date-picker` en lugar de reimplementarlo desde `core/shared/date` — el algoritmo de la cuadrícula del calendario es responsabilidad de date-picker y calendar es su vista de calendario. En cambio, las primitivas genéricas (`compareDate` / `isDateDisabled` / `isSameDay`) van directamente al núcleo compartido; calendar no depende en sentido inverso de la lógica de date-picker. Es el convenio de capas de «las primitivas generales se hunden, los algoritmos de dominio se quedan en su sitio».

**La tolerancia a intervalos invertidos**: tanto `isCalendarDateDisabled` como `clampDateToRange` llaman primero a `normalizeCalendarSpan` para normalizar el intervalo — que el usuario pase `[end, start]` (invertido) no provoca que todo se desactive ni un pinzado erróneo. La capa UI no obliga al llamador a ordenar primero.

**La normalización de `shiftCalendarMonth`**: `year * 12 + month + delta` y luego se vuelve a descomponer en año y mes; `((total % 12) + 12) % 12` maneja el módulo de números negativos — cuando el delta negativo cruza el año (por ejemplo, enero -2), el mes no se convierte en -1.

**La conmutación inmutable de la multiselección**: `toggleCalendarDate` elimina si ya está y, si no, lo añade y ordena cronológicamente — devuelve un array nuevo, utilizable directamente para una actualización reactiva, y con un orden estable (evita saltos visuales en la UI).

## Definiciones de tipos

```ts
export type LhCalendarRange = [Date, Date]
export type LhCalendarSelection = 'single' | 'range' | 'multiple'
```

La estructura de datos de la cuadrícula reutiliza `LhDatePickerDayData` (véase date-picker).

## Accesibilidad

La salida de `getCalendarCellAria` es contenida — **solo emite atributos cuando hay estado** (el convenio de `LhAriaAttrs` de omitir los valores falsos):

```ts
getCalendarCellAria({ date: selectedDate, selected: selectedDate, range: undefined })
// { 'aria-current': 'date' }

getCalendarCellAria({ date: new Date(2026, 0, 1), selected: null, range: [new Date(2026, 2, 1), new Date(2026, 3, 1)] })
// { 'aria-disabled': true }

getCalendarCellAria({ date: someDate, selected: null })
// {} (objeto vacío cuando no hay estado)
```

- El día seleccionado usa `aria-current="date"` (en lugar de `aria-selected`) — el calendario es un control de navegación y el convenio de APG usa current para expresar «la posición actual».
- Los días desactivados usan `aria-disabled`; los clics y la navegación por teclado de la capa UI deben saltarse esas casillas.
- Interacción de teclado: tras enfocar una casilla, ↑/↓/←/→ se mueven con `shiftCalendarDate(date, ±1|±7)` y Enter/Space disparan la selección.
- La cuadrícula completa debe llevar `role="grid"`, la misma estructura que el panel de date-picker.

## Ejemplos de uso

```ts
import {
  shiftCalendarMonth, normalizeCalendarSpan, toggleCalendarDate, isCalendarInSpan,
} from '@lh-ui/share/core/calendar'

shiftCalendarMonth(2026, 0, -2)   // { year: 2025, month: 10 } (módulo negativo correcto)
shiftCalendarMonth(2026, 11, 1)   // { year: 2027, month: 0 }
normalizeCalendarSpan(new Date(2026, 3, 1), new Date(2026, 2, 1))
// [2026-03-01, 2026-04-01] (el intervalo invertido se normaliza solo)
isCalendarInSpan(new Date(2026, 2, 15), new Date(2026, 2, 1), new Date(2026, 2, 28))  // true
isCalendarInSpan(new Date(2026, 2, 15), null, null)  // false (con cualquier extremo null)
toggleCalendarDate([new Date(2026, 2, 1)], new Date(2026, 2, 5))
// [2026-03-01, 2026-03-05] (añadido y ordenado)
toggleCalendarDate([new Date(2026, 2, 1), new Date(2026, 2, 5)], new Date(2026, 2, 1))
// [2026-03-05] (al coincidir, se elimina)
```

## Advertencias

- **month empieza en 0**: igual que date-picker y el `Date` nativo; la UI muestra `+1`.
- **La relación entre los tres modos de selección y core**: `LhCalendarSelection` es solo una declaración de tipos; las funciones de core son independientes del modo — `isCalendarSelected` gestiona single; `isCalendarInSpan`, range; `toggleCalendarDate`, multiple. El cableado del cambio de modo está en la capa UI.
- **El estado de medio intervalo**: cuando `rangeStart` ya está fijado y `rangeEnd` aún no, la casilla sobre la que pasa el cursor debe resaltar el tramo intermedio en tiempo real (la capa UI renderiza con un extremo temporal); el `generateCalendarDays` de core admite un rangeEnd nulo y no error.
- **El uso de `clampDateToRange`**: cuando el valor llega de fuera (por ejemplo, un `v-model` con una fecha fuera de rango), lo reconduce al intervalo legal; la capa UI lo llama una vez al observar el cambio del valor.
- **El rendimiento del panel permanente**: a diferencia de date-picker, que solo calcula la cuadrícula al abrir, calendar recalcula al cambiar de mes; no recalcules `generateCalendarDays` en cada fotograma (crea 35~42 objetos Date).
- **La frontera con date-picker**: ambos comparten los datos de la cuadrícula, pero **no el modelo de estado** — el `LhDatePickerState` de date-picker está orientado a la interacción de la capa emergente; calendar no tiene estado de visibilidad.
