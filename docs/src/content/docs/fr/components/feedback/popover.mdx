Popover est le « tooltip dans lequel on peut mettre des choses » : l'infobulle peut contenir des boutons, un formulaire, un menu, des images. Il ne remplace pas tooltip — qui ne peut contenir que du texte brut et interdit toute interaction ; il ne remplace pas non plus dialog — qui est modal et vole le focus. `core/popover` est aussi mince que tooltip, la différence est entièrement dans le **poids de l'interaction**.

## Quand l'utiliser

- Chaque framework implémente `<LhPopover>` : détails sous forme de carte, panneau de filtres, formulaire en ligne, groupe de boutons d'action.
- Les situations où l'utilisateur doit **rester dans la couche flottante et interagir**.
- **À ne pas utiliser pour** : une infobulle d'une seule phrase en texte brut (utilisez `tooltip`, plus léger et plus retenu) ; une confirmation forte qui doit interrompre le flux de l'utilisateur (utilisez `dialog`, modal) ; une confirmation d'opération (utilisez `popconfirm`, plus précis sémantiquement).

## Intentions de conception

**La raison d'être du délai de masquage de 100 ms** : tooltip se masque à 0 ms (disparition immédiate à la sortie), popover laisse 100 ms — **pour que le pointeur puisse aller du déclencheur jusqu'à la couche flottante** . Le déplacement de la souris du déclencheur à la couche fait brièvement sortir le pointeur de l'élément déclencheur, et un délai de 0 ms fermerait la couche en cours de route : l'utilisateur n'entrerait jamais. C'est la contrainte directe qu'impose l'interactivité du popover.

**`LH_POPOVER_TRIGGERS` comme constante de validation** : les modes de déclenchement sont une énumération finie (click/hover/focus/manual), exportée en tableau readonly pour la validation des props par la couche UI (validator de Vue, assertion d'exécution de React), et simultanément la contrepartie d'exécution du type TS.

**`role="dialog"` plutôt que `"tooltip"`** : WAI-ARIA impose qu'un tooltip ne contienne pas d'éléments interactifs ; une couche flottante interactive doit avoir la sémantique dialog. Avec `aria-labelledby` pointant vers l'élément de titre, le lecteur d'écran annonce le titre à l'ouverture plutôt que tout le contenu.

**L'interception de `canCloseOnEscape` quand disabled** : Esc ferme par défaut, et `disabled` l'empêche — à l'état désactivé, la couche flottante ne devrait de toute façon pas pouvoir être déclenchée ; cette garde évite qu'une couche déjà ouverte puisse encore être fermée par Esc après que le composant a été désactivé (sémantiquement, disabled signifie généralement « opérations verrouillées »).

**La flèche est optionnelle** : la classe `--arrow` n'est ajoutée que si `arrow !== false` — la flèche exige un calcul de positionnement supplémentaire (`computeArrowOffset` de `shared/popper`), une couche flottante purement informative peut l'éviter.

## Définitions de types

```ts
export type LhPopoverTrigger = 'click' | 'hover' | 'focus' | 'manual'

export interface LhPopoverState {
  placement?: LhPlacement        // 12 positions (shared/popper)
  trigger?: LhPopoverTrigger
  width?: string | number        // largeur de la couche flottante
  title?: string
  visible?: boolean
  disabled?: boolean
  arrow?: boolean                // true par défaut
  showAfter?: number
  hideAfter?: number
}
```

## Accessibilité

```ts
getPopoverTriggerAria(true, 'pop-1')
// { 'aria-expanded': true, 'aria-controls': 'pop-1', 'aria-haspopup': 'true' }
getPopoverTriggerAria(false)  // { 'aria-expanded': false, 'aria-haspopup': 'true' }

getPopoverPopperAria('pop-1', 'pop-1-title')
// { role: 'dialog', id: 'pop-1', 'aria-labelledby': 'pop-1-title' }
```

- **Le trio du déclencheur** : `aria-haspopup` déclare « je vais faire apparaître quelque chose », `aria-expanded` déclare « est-ce ouvert maintenant », `aria-controls` pointe vers « quel élément apparaît ». L'utilisateur au clavier s'appuie sur l'état expanded pour juger la situation.
- **`aria-controls` exige la présence de la couche** : l'id n'existe que lorsque la couche est rendue par `v-if` ; sans popperId transmis, seuls expanded/haspopup sont produits. **Ne faites pas pointer controls vers un élément démonté** — après fermeture, la couche est retirée et le controls du déclencheur reste suspendu (les lecteurs d'écran le tolèrent, mais une validation stricte signalera une erreur).
- **Le titre est la vitrine** : `aria-labelledby` pointe vers `<div class="lh-popover__title" :id="titleId">`. Le titre doit exprimer clairement ce qu'est cette couche flottante (« Critères de filtrage », « Détails de la commande »), pas un verbe (« Cliquez ici »).
- **La gestion du focus est l'affaire de la couche UI** : `role="dialog"` n'embarque pas de piégeage de focus — piéger ou non, et où placer le focus initial, est décidé par la couche UI avec `shared/focus-trap`. Un popover non modal ne piège généralement **pas** le focus (l'utilisateur garde accès au reste de la page), mais un clic à l'extérieur doit fermer.
- **Ouverture au clavier** : avec le déclenchement click, le déclencheur est un bouton et s'ouvre avec Entrée/Espace ; le déclenchement hover est inaccessible au clavier — **ne proposez pas seulement le survol pour les opérations essentielles**.

```ts
import {
  getDefaultDelay, getPopoverClass, getPopoverWidthStyle, canCloseOnEscape,
} from '@lh-ui/share/core/popover'

getDefaultDelay(undefined, undefined)  // { show: 200, hide: 100 }
getDefaultDelay(0, 0)                   // { show: 0, hide: 0 } (immédiat explicite)

getPopoverClass({ placement: 'bottom' })

getPopoverClass({ placement: 'top', arrow: false })

getPopoverClass({ placement: 'top', popperClass: 'my-pop' })
// ['lh-popover__popper', '…--top', '…--arrow', 'my-pop']

getPopoverWidthStyle(240)     // { width: '240px' }
getPopoverWidthStyle('50%')   // { width: '50%' }
getPopoverWidthStyle(undefined) // {}

canCloseOnEscape({ disabled: false })  // true
canCloseOnEscape({ disabled: true })   // false
```

## Remarques

- **La couche flottante doit être téléportée vers body** : laissée à sa position d'origine dans le DOM, elle se fera piéger par le `overflow: hidden`, le `transform` ou le contexte d'empilement `z-index` de son parent. Après téléportation, les coordonnées de positionnement sont calculées par `computePosition` de `shared/popper` sur la base du viewport.
- **La classe de position après retournement** : `getPopoverClass` consomme le **placement réellement effectif** (la valeur après le flip du popper), pas la valeur d'origine de la prop — sinon la flèche pointe dans une direction qui ne correspond pas au rendu visuel. La couche UI doit transmettre le placement réel renvoyé par le popper.
- **`width` et l'adaptation du contenu** : avec une largeur fixe, un contenu étroit sera étiré ; sans largeur, le contenu peut déborder du viewport. Pour un contenu complexe, il est recommandé de transmettre un `min-width` plutôt qu'un `width` (via un style personnalisé popperClass).
- **Le survol sur mobile** : l'écran tactile n'a pas de survol, un popover au déclenchement hover exige sur mobile un premier tap pour obtenir l'état « survolé », puis un tap ailleurs pour fermer — une très mauvaise expérience. Il est recommandé aux composants multiterminaux de basculer le mode de déclenchement selon la plateforme.
- **Popover imbriqués** : si la couche de A ouvre la couche de B, fermer A doit fermer B en cascade, sinon B reste suspendu. Soyez attentif lors du partage de l'état du popper.
- **Le déclenchement `manual`** : entièrement contrôlé par le `v-model:visible` externe — souvent associé à une logique du type « la ligne sélectionnée se déplie », auquel cas la fermeture au clic à l'extérieur est à écrire soi-même (la fermeture au clic à l'extérieur de core est également implémentée par la couche UI).
- **La réutilisation du code avec tooltip** : les deux partagent `shared/popper` et `shared/delay`, mais **les rôles aria ne sont pas interchangeables** — ne cédez pas à la réutilisation en appliquant le `role="tooltip"` de tooltip à une couche interactive : cela viole ARIA et le comportement des lecteurs d'écran devient imprévisible.
