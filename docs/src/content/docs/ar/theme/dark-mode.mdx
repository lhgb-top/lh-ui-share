تدعم جميع مكوّنات lh-ui **افتراضيًا الوضعين الفاتح والداكن**. فهذه ليست سمة أُضيفت
لاحقًا، بل فرضية تصميمية لنظام الرموز.

## آلية التبديل

مفتاح الوضع الداكن هو محدِّد CSS لا JS:

```scss
// styles/theme/common/var-dark.scss
[data-theme='dark'],
.dark {
  --lh-bg-color: #2A2520;
  --lh-text-primary: #E8E0D8;
  // ... 118 تجاوزًا
}
```

وطريقتان للتشغيل:

```html
<!-- الطريقة الأولى: سمة data (موصى بها، الدلالة أوضح) -->
<html data-theme="dark">

<!-- الطريقة الثانية: صنف (لتوافق الكود القديم / مكتبات تبديل الطرف الثالث) -->
<body class="dark">
```

كل ما على طبقة واجهة المستخدم (ConfigProvider في كل مكتبة أو كود العمل) فعله هو تبديل
هذه السمة / الصنف، **فتتبدّل ألوان جميع المكوّنات فورًا** — فمتغيرات CSS تُقيَّم في وقت
التشغيل دون أي تكلفة إعادة تصيير.

```ts
function toggleDark(isDark: boolean) {
  document.documentElement.dataset.theme = isDark ? 'dark' : 'light'
}
```

## الوضع الداكن طبقة تجاوز

لا يكتب ملف الوضع الداكن إلا **118 عنصرًا**، لا مجموعة كاملة من 185. فيُتجاوز فقط
الرموز التي تحتاج إلى الانقلاب، ويُفرَض الباقي عن القيم الفاتحة.

ومبدأ التصميم هو **إعادة توجيه الرموز الدلالية، لا إعادة كتابة كل مكوّن**:

```scss
// ✅ الأسلوب الجيد: في الوضع الداكن تشير إلى الرموز الدلالية الداكنة
[data-theme='dark'],
.dark {
  --lh-menu-item-color: var(--lh-text-primary);
  --lh-table-cell-color: var(--lh-text-primary);
}

// ❌ الأسلوب السيئ: كتابة لون ملموس ثابت في الوضع الداكن
[data-theme='dark'],
.dark {
  --lh-menu-item-color: rgba(255, 255, 255, 0.85);   // ينفصل عن text-primary، وتحتاج كل عملية ضبط لاحقة إلى تعديلين
}
```

## فخ الخبز في وقت الترجمة

هو **الفخ الأكثر وقوعًا** في الوضع الداكن، وهو سبب وجود البند السابع من
`verify:styles`.

### مبدأ الفخ

الرموز التي تأخذ في `var.scss` قيمًا بصيغة `#{$lh-foo}`:

```scss
// var.scss
:root {
  --lh-menu-item-color: #{$lh-menu-item-color};   // يُستبدل متغير SCSS في وقت الترجمة بقيمة فاتحة ملموسة
}
```

تُخبَز متغيرات SCSS **في وقت الترجمة إلى قيم حرفية**، فتعادل:

```scss
:root {
  --lh-menu-item-color: rgba(0, 0, 0, 0.88);   // لا ينقلب تلقائيًا في الوضع الداكن!
}
```

والنتيجة: في الوضع الداكن تبقى نصوص القوائم / الجداول / الخطوط الزمنية تأخذ قيمًا
فاتحة، فلا تظهر (**أسود فوق أسود**). وقد وقع نقص كهذا فعلًا، وسجلَّت عملية تداركه في
changeset الإصدار 0.4.0.

### الحل

إعادة توجيه صريحة إلى الرموز الدلالية الداكنة داخل `var-dark.scss`:

```scss
[data-theme='dark'],
.dark {
  --lh-menu-item-color: var(--lh-text-primary);
}
```

### سلسلة fallback تُقيَّم في وقت التشغيل فهي آمنة

سلسلة fallback داخل SCSS المكوّن:

```scss
.lh-button {
  color: var(--lh-foo, var(--lh-bar, #333));
}
```

يُقيَّم fallback الخاص بـ `var()` **في وقت التشغيل**: ما دام أي رمز في السلسلة لديه
تجاوز داكن، تتبعه السلسلة كلها وتنقلب. **دون الحاجة إلى إعادة التصريح**.

جدول المقارنة:

| الأسلوب | وقت التقييم | السلوك في الوضع الداكن |
| --- | --- | --- |
| `var(--lh-foo, fallback)` | وقت التشغيل | ✅ ينقلب إذا كان رمز في السلسلة لديه تجاوز داكن |
| `#{$lh-foo}` (إقحام SCSS) | وقت الترجمة | ❌ يُخبَز بالقيمة الفاتحة، ويحتاج إلى إعادة توجيه صريحة في var-dark |
| دوال SCSS مثل `mix($lh-a, $lh-b)` | وقت الترجمة | ❌ مماثل لما سبق |

## تفتيح الوضع الداكن للمسبقات ذات اللون الرئيسي الداكن

من بين المسبقات الداخلية الخمس، ذات اللون الرئيسي الداكن (青花瓷 / 朱砂 / 水墨) يغوص
لونها الرئيسي في لون خلفية الصفحة في الوضع الداكن. ويتولى `buildPresetDarkVars`
المعالجة تلقائيًا:

قاعدة الحكم: إذا كانت نسبة تباين `--lh-primary-color` مقابل خلفية الصفحة الداكنة
`#1A1A2E` (`DARK_PAGE_BG`) أقل من 3 (`DARK_PRIMARY_CONTRAST_THRESHOLD`) يُحكَم بأنه
لون رئيسي داكن، ثم:

```css
[data-theme='dark'],
.dark {
  --lh-primary-color: color-mix(in srgb, <قيمة حرفية> 55%, #fff);   /* تفتيح 55% */
  --lh-primary-color-hover: color-mix(in srgb, var(--lh-primary-color) 70%, #fff);
  --lh-primary-color-active: color-mix(in srgb, var(--lh-primary-color) 85%, #000);
  --lh-color-on-primary: #101410;   /* بعد التفتيح يصبح تباين النص الأبيض غير كافٍ، فيُستبدل بالنص الأسود */
  --lh-primary-color-bg: color-mix(in srgb, var(--lh-primary-color) 25%, transparent);
  --lh-selected-color: color-mix(in srgb, var(--lh-primary-color) 40%, #fff);
}
```

**لماذا يُعوَّض اللون الرئيسي المُفتَّح بقيمة حرفية لا `var()`**: لأن
`color-mix(in srgb, var(--lh-primary-color) 55%, #fff)` يُنشئ دورة CSS ذاتية الإشارة
(تشير قيمة `--lh-primary-color` إلى نفسها). ولذلك تُعوَّض هذه القيمة **بالقيمة
الحرفية**، بينما تستخدم البقية `var()` وتتبع اللون الرئيسي الحالي.

أما المسبقات ذات اللون الرئيسي الفاتح (松花绿 / 藤黄) فلا تحتاج إلى تفتيح، لكنها تحصل
مع ذلك على إعادة تعريف داكنة لـ `--lh-primary-color-bg` و `--lh-selected-color`.

## دلالة ترتيب حقن المسبقة

النص الذي يُولِّده `buildPresetStyleText` يضع كتلة `:root { ... }` أولًا ثم كتلة
`[data-theme='dark'], .dark { ... }`. **وعند تساوي الخصوصية يغلب الأخير**، لذلك لا
تتسرّب القيمة الفاتحة لـ `--lh-selected-color` المُعلَن عنها في `:root` للمسبقات ذات
اللون الرئيسي الفاتح إلى الوضع الداكن.

وهذا أيضًا السبب الجذري لقاعدة «يكتب `<style>` فقط لا style مضمَّن» — فخصوصيةstyle
المضمَّن 1,0,0,0 تطغى على كتلة متغيرات الوضع الداكن الكاملة في `var-dark.scss`،
فيفشل الوضع الداكن مباشرةً (لمزيد من التفاصيل انظر
[النظرة العامة على السمة](/ar/theme/overview#قيد-الحقن-كتابة-style-فقط-لا-style-مضمَّن)).

## كيفية التحقق من اكتمال الوضع الداكن

ثلاث وسائل من الأضعف إلى الأقوى:

1. **البند السابع من `pnpm verify:styles` (إمكانية الوصول الداكنة)**: فحص ساكن، يجد
   الرموز «المخبوزة فاتحة دون تجاوز في var-dark». وهذه بوابة CI.
2. **`pnpm verify:theme` (AA 4.5:1)**: يقرأ مخرجات `es/` ويحسب نسب تباين المسبقات في
   الوضعين الفاتح والداكن. يتطلب تشغيل `pnpm build` أولًا. لا يُشغَّل في CI، بل يحرسه
   المستخدم يدويًا.
3. **الفحص البصري**: تبديل الوضع الداكن في موقع docs / ساحات تجربة كل مكتبة ومراجعة
   كل مكوّن.

قائمة مراجعة ذاتية عند إضافة رمز جديد:

- [ ] هل يحتاج هذا الرمز إلى الانقلاب في الوضع الداكن؟
- [ ] إن احتاج، هل أُضيف تجاوز في `var-dark.scss`؟
- [ ] هل قيمته على الصيغة `#{$lh-*}` إقحام؟ (نعم → يجب إضافة تجاوز داكن)
- [ ] هل يستهلكه المكوّن عبر سلسلة `var(--lh-x, fallback)`؟

## المعروف المتبقي

تم في 0.4.0 تدارك نقص الوضع الداكن بشكل منهجي (مشكلة عدم ظهور نصوص القوائم /
الجداول / الخطوط الزمنية، انظر changeset). أما البنود المعروفة المتبقية فتُعالج مع
«مشروع رموز الارتفاع» لاحقًا.
