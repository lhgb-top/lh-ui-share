الشجرة هي الحاوية العامة للبيانات الهرمية: أدلة الملفات، وهياكل المؤسسات، وأشجار الصلاحيات، والقوائم المتسلسلة. ووعورتها في **إدارة حالة البنية العودية** — فالتوسيع والتحديد والتحميل الكسول كلها عمليات على شجرة فرعية بأكملها، مع التعامل مع البيانات ذات المراجع الدائرية، والعُقد المعطَّلة، والحالة النصفية. وقد جمع `core/tree` هذه الخوارزميات بالدوال الصرفة + التحديث غير القابل للتغيير.

## متى يُستخدم

- عندما يُطبّق كل طرف `LhTree`: تصفُّح الأدلة، وتوزيع الصلاحيات، وعرض الهيكل التنظيمي، وتصفية التصنيفات.
- البيانات الهرمية التي تحتاج إلى توسيع/طي، وتحديد (يشمل ربط الأب بالأبناء)، وتحميل كسول.
- **لا يجب استخدامه**: التصنيفات المسطَّحة بمستويين كحد أقصى (الاختيار المتسلسل أو المتحكم المجزَّأ أوفر جهدًا)؛ والقوائم الخطية (استخدم `virtual-list`).

## نية التصميم

**التصيير هو التسطيح**: الشجرة في الواجهة في جوهرها **قائمة بمستويات إزاحة داخلية**. يجتاز `flattenTree` أولًا بالعمق، ولا يُوسِّع سوى الأشجار الفرعية التي يصيبها `expandedKeys`، ويُخرِج مصفوفة مسطَّحة (يحمل كل عنصر `level` / `parentKey` / `ancestorKeys`).فيقوم طرف العرض بـ v-for على مصفوفة أحادية البعد — وهو أبسط بكثير من المكوّن العودي، ومتوافق بطبيعته مع التمرير الافتراضي.

**الحكم بالتكرار عبر سلسلة الأجداد مقابل الحكم العام**: تستخدم الدوال العودية في هذه الوحدة عمومًا **seen بسلسلة الأجداد** (`ancestors` / `nextSeen` تُمرَّر طبقةً تلو الأخرى) لا Set عامًّا. وثمن ذلك أن الحماية نافذة فقط داخل الاستدعاء الواحد، لكن فائدتها أن **الأشجار الفرعية المشتركة قانونًا في DAG لا يُخطَأ تخطيها**، ولا يوجد تسريب حالة عبر النسخ. ولاحظ أن هذا يختلف عن مفاضلة `flattenLeafColumns` في `table` (الذي يستخدم seen عامًّا) — فمشاركة DAG في الجدول يجب أن تُنبَثق مرة واحدة فقط (لمحاذاة عدد الأعمدة)، بينما مشاركة DAG في الشجرة يجب أن تُحسَب مرة لكل مسار مختلف.

**العُقدة المعطَّلة لا تدخل مقام التحديد الكامل**: تتخطى `collectCheckableLeafKeys` الأشجار الفرعية المعطَّلة — وإلا فبعد تحديد الأب سيبقى **في حالة indeterminate دائمًا** لأن الأبناء المعطَّلين ناقصون، ولن يصبح محددًا بالكامل أبدًا. وهذا نوع حقيقي من أخطاء التجربة.

**العُقدة غير الورقية غير المُحمَّلة**: عندما يكون `isLeaf !== true` ولا توجد `children`، تُرجِع `collectCheckableLeafKeys` مصفوفة فارغة، لكن `toggleCheckKeys` يكتب **مفتاحها نفسه** في `checkedKeys` — ففي سيناريو التحميل الكسول يمكن للمستخدم تحديد عُقدة لم تُحمَّل أبناؤها بعد، ثم يُترَك الأمر لطرف العرض بعد التحميل في أن يُسلسل أو لا.

**`moveTreeFocus` مهمل @deprecated**: التقت خوارزمية التنقل في `core/shared/keyboard.getNextListIndex`، ويحتفظ هذا الغلاف بالتوقيع القديم والدلالة القائمة «الرجوع إلى العنصر الأول عند بطلان القيمة الحالية».

## جدول الدوال

| الدالة | التوقيع | القيمة المُعادة | الدور |
| --- | --- | --- | --- |
| `isTreeNodeLeaf` | `(node) => boolean` | هل هي ورقة | الأولوية لـ `isLeaf`، وإلا يُستنتَج من children |
| `flattenTree` | `(nodes, expandedKeys, …) => LhFlatTreeNode[]` | قائمة مسطَّحة | لا يُوسِّع سوى الأشجار المصابة |
| `getDescendantKeys` | `(node, seen?) => string[]` | مفاتيح الأحفاد | حكم سلسلة الأجداد |
| `findTreeNode` | `(nodes, key, seen?) => LhTreeNode \| null` | العُقدة | بحث بالعمق |
| `getNodeCheckState` | `(node, checkedKeys, checkStrictly?) => LhTreeCheckState` | ثلاثي الحالات | الشجرة الفرعية المعطَّلة لا تُحتسَب في المقام |

| `isNodeLoadable` | `(node, lazy, loadedKeys) => boolean` | هل يُحمَّل | غير مُصرَّح بكونه ورقة وغير محمَّل |

## تعريف الأنواع

```ts
export interface LhTreeNode {
  key: string
  label: string
  children?: LhTreeNode[]
  disabled?: boolean
  isLeaf?: boolean       // إن لم يُمرَّر يُستنتَج من children
}

export interface LhFlatTreeNode {
  node: LhTreeNode
  key: string
  level: number                 // بدءًا من 0
  parentKey: string | null
  ancestorKeys: string[]        // سلسلة الأجداد (لا تشمل العُقدة نفسها)
  isLeaf: boolean
}

export type LhTreeCheckState = 'checked' | 'indeterminate' | 'unchecked'
```

## إمكانية الوصول

تُخرِج `getTreeAria` / `getTreeNodeAria` الدلالات الكاملة لنمط treeview في APG:

```ts
getTreeAria('lh-tree-1')  // { role: 'tree', id: 'lh-tree-1' }

getTreeNodeAria({ level: 2, expanded: true, selected: true, checked: 'indeterminate' })
// { role: 'treeitem', 'aria-level': 2, 'aria-expanded': true,
//   'aria-selected': true, 'aria-checked': 'indeterminate' }

getTreeNodeAria({ level: 1, leaf: true })
// { role: 'treeitem', 'aria-level': 1 }  ← العُقدة الورقية لا تُخرِج aria-expanded
```

- يبدأ `aria-level` من 1 (لاحظ أن `level` في `flattenTree` يبدأ من 0، فعند تمريره إلى aria **زِدْه 1**).
- **العُقدة الورقية لا تُخرِج `aria-expanded`** — تجنبًا لقيمة `aria-expanded="false"` بلا معنى، وهذا ما تنص عليه APG صراحةً.
- القيم الثلاث لـ `aria-checked`: `true` / `false` / `'indeterminate'` (سلسلة نصية).
- التفاعل بلوحة المفاتيح (treeview في APG): ↑/↓ للتنقل بين العُقد المرئية، و→ للتوسيع/الدخول إلى العُقدة الابنة، و← للطي/الرجوع إلى العُقدة الأب، وHome/End للوصول إلى الأولى والأخيرة، وEnter لتشغيل التحديد.
- **مصدر `aria-level` بعد التسطيح**: هو `level + 1` من `flattenTree`، فلا تستنتجه من عمق الإزاحة في DOM.

## أمثلة الاستخدام

```ts
import { flattenTree, toggleCheckKeys, getNodeCheckState } from '@lh-ui/share/core/tree'

const tree = [
  { key: '1', label: 'قسم البحث والتطوير', children: [
    { key: '1-1', label: 'فريق الواجهة الأمامية', children: [{ key: '1-1-1', label: 'lh-ui' }] },
    { key: '1-2', label: 'فريق الواجهة الخلفية' },
  ]},
  { key: '2', label: 'قسم المنتج' },
]

flattenTree(tree, ['1'])
// [قسم البحث والتطوير(l0), فريق الواجهة الأمامية(l1), فريق الواجهة الخلفية(l1), قسم المنتج(l0)]
// لاحظ غياب 1-1-1: لأن '1-1' ليست ضمن expandedKeys

flattenTree(tree, ['1', '1-1'])
// [قسم البحث والتطوير, فريق الواجهة الأمامية, lh-ui(l2), فريق الواجهة الخلفية, قسم المنتج]

toggleCheckKeys(tree, [], '1')
// ['1', '1-1', '1-1-1', '1-2'] (تحديد كل الأحفاد تسلسليًّا، مع العُقدة نفسها)

toggleCheckKeys(tree, ['1', '1-1', '1-1-1', '1-2'], '1-1-1')
// ['1-2']  —— بعد إلغاء '1-1-1' يرجع التسلسل: '1-1' لم تعد محدَّدة بالكامل فتُحذَف،
// و'1' لم تعد محدَّدة بالكامل أيضًا فتُحذَف (الرجوع يمتد إلى الجذر)

toggleCheckKeys(tree, ['1-1'], '1-2')
// ['1-1', '1-2']  —— رجوع إلى الأجداد فقط، دون باقي الفروع

getNodeCheckState(tree[0], ['1', '1-1', '1-1-1', '1-2'])  // 'checked' (جميع الأوراق القابلة للتحديد محدَّدة)
getNodeCheckState(tree[0], ['1-1-1'])                      // 'indeterminate' (واحدة من أصل ورقتين قابلتين للتحديد)
getNodeCheckState(tree[0], ['1-1'])                        // 'unchecked' ('1-1' ليست ورقة، فلا تُحتسَب)
getNodeCheckState(tree[0], [])                             // 'unchecked'
```

## ملاحظات

- **`level` يبدأ من 0 و`aria-level` يبدأ من 1** — وهذا أكثر موضع يسهو فيه المستخدم في هذه الوحدة، فلا بد من `+1` عند ربط `aria-level`.
- **نطاق نفاذ حكم سلسلة الأجداد**: الحماية نافذة فقط داخل الاستدعاء الواحد. فاستدعاءان مستقلان لـ `findTreeNode` على الشجرة نفسها يحكمان كلٌّ منهما على حدة، ويُجتاز الشجرة الفرعية المشتركة مرتين — وهذا مقصود (مشاركة DAG قانونية)، وليس خطأً.
- **`checkStrictly` (لا ربط بين الأب والأبناء)**: تصبح `getNodeCheckState` ثنائية الحالات، ولا يُغيِّر `toggleCheckKeys` سوى مفتاح العُقدة نفسه، دون رجوع إلى الأجداد. وشائعة الاستخدام في سيناريوهات توزيع الصلاحيات.
- **الثابت المتعلق بتسلسل العُقد المعطَّلة**: يتخطى رجوع الأجداد في `toggleCheckKeys` الأب المعطَّل — فلا يُعاد كتابة مفتاحه بالتسلسل. وإن احتاج العمل إلى «تحديد أب معطَّل برمجيًّا»، فليُعامَل `checkedKeys` مباشرة بدلًا من استخدام هذه الدالة.
- **`isLeaf` له الأولوية على `children`**: العُقدة المُصرَّح لها بـ `isLeaf: true` تُعالَج كورقة حتى لو كان لها `children` (شائع في التحميل الكسول: التصريح بالورقة يمنع التوسيع).
- **عدم قابلية التغيير في `mergeLoadedChildren`**: تُرجِع شجرة جديدة ولا تُعدِّل `nodes` المُمرَّرة — فـ props.data يملكه المستخدم، والتعديل المباشر يكسر تدفق البيانات في اتجاه واحد.
- **أداء `flattenTree`**: إعادة حساب كاملة في كل مرة تتغير فيها expandedKeys. فعند المستويات العميقة + البيانات الضخمة فكِّر في memo للأشجار الفرعية (تخزين مؤقت في طرف العرض مجمَّع بحسب parentKey).
- **البيانات ذات المراجع الدائرية**: جميع الدوال العودية محميَّة بحكم سلسلة الأجداد فلا تدور في حلقة لا نهائية — ولكن **وجود حلقة في البيانات نفسها خطأٌ في حد ذاته**، والحكم يمنع انهيارها فحسب.
