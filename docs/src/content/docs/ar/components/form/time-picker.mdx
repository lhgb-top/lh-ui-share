اختيار الوقت تفاعل **بثلاثة أعمدة دوّارة** (ساعة/دقيقة/ثانية): يدير المستخدم كل عمود على حدة، بدلاً من كتابة الأرقام في حقل إدخال واحد. ويتولّى `core/time-picker` تحليل سلسلة النسق ذي العرض الثابت وعكسه، وتوليد الأعمدة وفق الخطوة، وتصفية القيم المسموحة والالتفاف، إضافة إلى دلالة APG لكل من dialog و listbox. ويدعم الوضعين `time` (الوقت وحده) و `date-time` (التاريخ + الوقت).

## متى يُستخدم

- تُنجزه الأطراف على هيئة `LhTimePicker`: مواعيد الحجز، والمهام المجدولة، وإعداد ساعات العمل.
- القيمة «لحظة زمنية» بدقة تصل إلى الدقيقة أو الثانية.
- **لا ينبغي استخدامه**: عند الحاجة للتاريخ دون الوقت (استخدم `date-picker`)؛ وللتمديد الزمني (استخدم time-picker مرتين أو الوضع `isRange`).

## القصد التصميمي

يستخدم `parseTime` / `formatTime` **رموزاً ذات عرض ثابت** (`HH` / `mm` / `ss` لكل منها خانتان) بدلاً من مكتبة تواريخ عامة، وهو اختيار مقصود: فالوقت له ثلاثة مكوّنات فقط، والتحليل الموضعي `substring(idx, idx+2)` أخف بكثير من التعابير النمطية أو moment، وهو متناظر تماماً مع `formatTime` — فما يُكتب يمكن تحليله عائداً. وعند فشل التحليل تُعادة null دائماً، دون إعادة بيانات قذرة جزئية.

وقد أُضيف وقاية لخطوة `generateTimeColumn`: القيمة غير الموجبة تُوحَّد إلى 1 (فالقيمة `step: 0` تُدخل حلقة `for` في دوران لا ينتهي)، وتُقَرَّب الكسور (فتصبح `step: 2.5` هي 2). أما `wrapTimeValueInRange` فcd يُعيد القيمة الأصلية **عندما يغطي المجال كامل المدى** — وهو توافق مع السلوك القديم: فإذا كان مجال عمود الساعات هو [0,23]، يجب أن يقف التدوير عند الحد عند تجاوزه لا أن يلتف إلى الطرف الآخر؛ ولا يحدث الالتفاف إلا عند تحديد فترة جزئية صراحةً (مثل [9, 18]). أما `clampTimeValue` فعلى العكس من ذلك، يكلِّئ دائماً داخل المجال، ويُستخدم لجلب القيمة المختارة سلفاً إلى المجال الصالح.

## تعريفات الأنواع

```ts
export type LhTimePickerMode = 'time' | 'date-time'
export type LhTimeColumnType = 'hour' | 'minute' | 'second'

export interface LhTimeData {
  hours: number
  minutes: number
  seconds: number
}

export interface LhTimeColumn {
  value: number
  text: string
  isSelected: boolean
  isDisabled: boolean
}

export interface LhTimePickerOptions {
  hours?:   { step?: number; disabledHours?:   () => number[] }
  minutes?: { step?: number; disabledMinutes?: (hour: number) => number[] }
  seconds?: { step?: number; disabledSeconds?: (hour: number, minute: number) => number[] }
}

export interface LhTimeSelectEventData {
  column: LhTimeColumnType
  value: number
}
```

## إمكانية الوصول

يظهر لوح الوقت في نافذة **dialog** عائمة (المُطلِق `aria-haspopup="dialog"`)، وكل عمود من أعمدته الثلاثة هو **listbox**. وتأتي هذه الدلالة من `getPopupTriggerAria` في النواة المشتركة:

```ts
getTimePickerTriggerAria(true, 'lh-time-panel')
// { 'aria-expanded': true, 'aria-haspopup': 'dialog', 'aria-controls': 'lh-time-panel' }

getTimePickerPanelAria('lh-time-panel')
// { role: 'dialog', id: 'lh-time-panel' }

getTimePickerColumnAria('الساعات')
// { role: 'listbox', 'aria-label': 'الساعات' }
```

- يجب أن تحمل خيارات العمود `role="option"` + `aria-selected` (تُصدِّرها طبقة UI من `LhTimeColumn.isSelected`) + `aria-disabled` (من `isDisabled`).
- لوحة المفاتيح: بعد تركيز العمود يتنقّل ↑/↓ بين الخيارات **غير المعطَّلة** ويختارها؛ ويغلق Esc اللوحة.
- تعني دلالة dialog أنه عند توسيع اللوحة يجب تقييد التركيز (`core/shared/focus-trap`)، كي لا يهرب التركيز خارج اللوحة.

## أمثلة الاستخدام

```ts
import {
  parseTime, formatTime, generateTimeColumn, isValidTime, createDateTime,
} from '@lh-ui/share/core/time-picker'

formatTime(9, 30, 5)                    // '09:30:05'
formatTime(9, 30, 5, 'HH:mm')           // '09:30'
parseTime('09:30:05')                   // { hours: 9, minutes: 30, seconds: 5 }
parseTime('09:30:05', 'HH:mm')          // { hours: 9, minutes: 30, seconds: 0 } (تُكمل ss الناقصة بصفر)
parseTime('99:99:99')                   // null (قيم المجال غير صالحة)
parseTime('abc', 'HH:mm:ss')            // null (NaN)
parseTime('09:30', 'YYYY-MM-DD')        // null (لا يحوي format رموز وقت)
generateTimeColumn('hour', 1)           // 24 عنصراً: 00..23
generateTimeColumn('minute', 15)        // 4 عناصر: 00 15 30 45
generateTimeColumn('minute', 0)         // 60 عنصراً (تُوحَّد step 0 إلى 1)
generateTimeColumn('hour', 1, [0, 1, 2])// العناصر الثلاثة الأولى isDisabled: true
isValidTime(23, 59, 59)                 // true
isValidTime(24, 0, 0)                   // false
createDateTime(new Date('2026-10-12'), 9, 30, 0)  // 2026-10-12 09:30:00
```

## ملاحظات

- **يجوز أن يكون ترتيب رموز format عشوائياً**: فكلٌ من `formatTime` و `parseTime` يأخذ القيم وفق موضع الرمز في format، ويتطابق `'mm:HH` ذهاباً وإياباً بشكل صحيح. لكن عند خلط رموز مع أحرف ليست رموزاً (مثل `'HH时mm分'`)، يأخذ `parseTime` دائماً بخانتين ثابتتي العرض، ولا تؤثر الأحرف الصينية (لأنها ليست رموزاً)، لكن **ستكون فواصل الأرقام في موضع خاطئ** — ففي `'09点30'` يلتقط موضع `mm` السلسلة `'点3'`، فتُحلَّل NaN وتُعاد null. فاحرص على أن يحتوي format على الرموز وفواصل غير رقمية فقط.
- **سلبيات `parseTime`**: يُعاد null بدلاً من طرح استثناء، وعلى طبقة UI معالجة null عند فقدان تركيز حقل الإدخال (يُحتفظ عادةً بالقيمة الأصلية مع تنبيه).
- **تفاعل الخطوة مع التعطيل**: تكتفي `disabledValues` بوسم التعطيل دون تصفية — فعلى تنقّل لوحة المفاتيح في طبقة UI تجاوز العناصر `isDisabled` بنفسها.
- **الوضع `date-time`**: يتولى `date-picker` جزء التاريخ، ويُعاد استخدام هذا الموديل لجزء الوقت؛ وعادةً يُنتقى التاريخ في اللوحة قبل الوقت، ويُدمجهما `createDateTime(baseDate, …)`، مع الانتباه إلى أنه عندما يكون `baseDate` مساوياً null تُؤخذ تاريخ اللحظة الحالية.
- **الوضع `isRange`**: `rangeStart` / `rangeEnd` هما قيمتا `LhTimeData`، ويعتمد عمود القيم المعطَّلة الثاني على اختيار الأول (مثل اشتراط أن يكون وقت الانتهاء لاحقاً لوقت البداية)، وتحسبه طبقة UI ديناميكياً بالاستدعاءات `getDisabledMinutes` ونحوها.
- **`SS` بالأحرف الكبيرة ليست الثواني**: الثواني هي `ss` الصغيرة فقط، و `HH` كبيرة و `mm`/`ss` صغيرة هي كتابة ثابتة، تتسق مع اصطلاحات مكتبات مثل day.js.
