Time picking is the interaction of **three scrolling columns** (hours/minutes/seconds): the user spins each column separately instead of typing numbers into one input box. `core/time-picker` handles parsing and formatting of fixed-width format strings, column generation by step, filtering and wrapping of selectable value domains, and APG dialog + listbox semantics. It supports two modes: `time` (pure time) and `date-time` (date + time).

## When to use

- Each port implements `LhTimePicker`: appointment times, scheduled tasks, business-hours settings.
- Scenarios where the value is a "time of day" with minute or second granularity.
- **Should not use it**: when only a date is needed without a time (use `date-picker`); for a time span (use two time-pickers or the range mode `isRange`).

## Design intent

`parseTime` / `formatTime` use **fixed-width tokens** (`HH` / `mm` / `ss` each occupy 2 characters) instead of a general date library — a deliberate trade-off: time has only three components, and positional parsing via `substring(idx, idx+2)` is far lighter than regex or moment, and it is strictly symmetric with `formatTime` — what you write is what you get back. Parse failures always return null, never partially returned dirty data.

`generateTimeColumn`'s `step` is defensive: non-positive values normalize to 1 (`step: 0` would make the `for` loop spin forever), and decimals are floored (`step: 2.5` becomes 2). `wrapTimeValueInRange` **returns the original value when the range covers the full domain** — this is legacy-behavior compatibility: for example, if the hour column's range is [0,23], scrolling past the boundary should stop at the edge rather than wrap to the other end; wrapping happens only when a sub-interval is explicitly constrained (like [9, 18]). `clampTimeValue` does the opposite, always clamping into the interval; it is used to collapse an existing selected value back into the legal range.

## Accessibility

The time panel pops up as a **dialog** (the trigger has `aria-haspopup="dialog"`), and the three columns inside the panel are each a **listbox**. This set of semantics comes from the shared kernel's `getPopupTriggerAria`:

```ts
getTimePickerTriggerAria(true, 'lh-time-panel')
// { 'aria-expanded': true, 'aria-haspopup': 'dialog', 'aria-controls': 'lh-time-panel' }

getTimePickerPanelAria('lh-time-panel')
// { role: 'dialog', id: 'lh-time-panel' }

getTimePickerColumnAria('Hours')
// { role: 'listbox', 'aria-label': 'Hours' }
```

- Options inside a column should have `role="option"` + `aria-selected` (the UI layer renders `LhTimeColumn.isSelected`) + `aria-disabled` (`isDisabled`).
- Keyboard: after a column is focused, ↑/↓ move between **non-disabled** options and select them; Esc closes the panel.
- The dialog semantics mean focus should be trapped when the panel is open (`core/shared/focus-trap`), so focus does not escape the panel.

## Usage examples

```ts
import {
  parseTime, formatTime, generateTimeColumn, isValidTime, createDateTime,
} from '@lh-ui/share/core/time-picker'

formatTime(9, 30, 5)                    // '09:30:05'
formatTime(9, 30, 5, 'HH:mm')           // '09:30'
parseTime('09:30:05')                   // { hours: 9, minutes: 30, seconds: 5 }
parseTime('09:30:05', 'HH:mm')          // { hours: 9, minutes: 30, seconds: 0 } (missing ss defaults to 0)
parseTime('99:99:99')                   // null (values out of domain)
parseTime('abc', 'HH:mm:ss')            // null (NaN)
parseTime('09:30', 'YYYY-MM-DD')        // null (format has no time tokens)
generateTimeColumn('hour', 1)           // 24 items: 00..23
generateTimeColumn('minute', 15)        // 4 items: 00 15 30 45
generateTimeColumn('minute', 0)         // 60 items (step 0 normalized to 1)
generateTimeColumn('hour', 1, [0, 1, 2])// first three items have isDisabled: true
isValidTime(23, 59, 59)                 // true
isValidTime(24, 0, 0)                   // false
createDateTime(new Date('2026-10-12'), 9, 30, 0)  // 2026-10-12 09:30:00
```

## Caveats

- **The token order in format can be arbitrary**: both `formatTime` and `parseTime` read by token position within the format, so `'mm:HH'` also round-trips correctly. But when non-token characters are mixed in (like `'HH时mm分'` — a Chinese-locale format meaning `HH` hours, `mm` minutes), `parseTime` still slices at a fixed 2-character width — non-Latin characters do not matter (they are not tokens), but **numeric separators get misaligned** — in `'09点30'` (meaning 09 o'clock 30), the `mm` position slices into `'点3'`, which parses to NaN and returns null. Keep the format to only tokens and non-numeric separators.
- **`parseTime` tolerance**: it returns null instead of throwing; the UI layer must handle null when the input loses focus (usually keeping the original value and showing a hint).
- **Interaction between step and disabling**: `disabledValues` only marks things disabled, it does not filter — the UI layer's keyboard navigation must skip `isDisabled` items itself.
- **`date-time` mode**: the date part is handled by `date-picker`, and the time part reuses this module; the panel usually picks the date first and then the time, and `createDateTime(baseDate, …)` merges the two. Note that when `baseDate` is null, the **current moment's** date is used.
- **Range mode `isRange`**: `rangeStart` / `rangeEnd` are two `LhTimeData` values, and the second column's disabled values depend on the first column's selection (e.g. the end time must be later than the start); the UI layer computes this dynamically with callbacks like `getDisabledMinutes`.
- **Uppercase `SS` is not seconds**: only lowercase `ss` is seconds; `HH` uppercase and `mm`/`ss` lowercase is the fixed spelling, consistent with libraries like day.js.
