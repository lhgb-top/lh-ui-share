Tokens are the variables of the design language: colors, font sizes, spacing, radii, shadows, and animation durations are all named as `--lh-*` CSS variables, and components consume the names instead of hardcoding values. Re-skinning is just swapping tokens.

## Three token layers

| Layer | Location | Count | Evaluation time | Overridability |
| --- | --- | --- | --- | --- |
| CSS variables · light | `:root` in `styles/theme/common/var.scss` | **185** | Runtime | ✅ Override anywhere |
| CSS variables · dark | `[data-theme='dark'], .dark` in `styles/theme/common/var-dark.scss` | **118** | Runtime | ✅ |
| SCSS variables | `styles/theme/common/variables.scss` | **183** | **Compile time** | ⚠️ Source edit + recompile only |

### Light tokens (var.scss)

```scss
:root {
  --lh-primary-color: #2B5FA6;
  --lh-text-primary: rgba(0, 0, 0, 0.88);
  --lh-bg-color: #ffffff;
  --lh-border-color: #e5e6eb;
  --lh-radius-base: 6px;
  --lh-spacing-base: 8px;
  // ... 185 entries
}
```

### Dark overrides (var-dark.scss)

```scss
[data-theme='dark'],
.dark {
  --lh-bg-color: #14141F;
  --lh-text-primary: rgba(255, 255, 255, 0.85);
  --lh-border-color: #3A3A4A;
  // ... 118 entries
}
```

Dark mode is an **override layer**, not a separate set: it only writes the 118 tokens that need to flip; the rest keep their light values.

### SCSS variables (variables.scss)

```scss
$lh-primary-color: #2B5FA6 !default;
$lh-border-radius-base: 6px !default;
// ... 183 entries
```

SCSS variables exist to **participate in compile-time computation**: color mixing (`mix()` / `shade()`), shadow composition (adding multiple shadow layers) — things CSS variables cannot do. The cost is being **baked at compile time**, so they do not flip automatically in dark mode.

## The layered structure of tokens

Tokens fall into three semantic tiers:

```scss
// 1. Base palette (the lowest layer, not consumed directly by components)
--lh-blue-6: #2B5FA6;
--lh-red-6: #F5222D;

// 2. Semantic tokens (this is the layer components consume)
--lh-primary-color: var(--lh-blue-6);
--lh-error-color: var(--lh-red-6);
--lh-text-primary: rgba(0, 0, 0, 0.88);
--lh-bg-color: #ffffff;

// 3. Component tokens (specialized values for individual components)
--lh-button-radius: var(--lh-radius-base);
--lh-switch-knob-color: #fff;
```

**Components only consume layers 2 and 3.** Changing the palette (layer 1) cascades into all semantic tokens — this is the lever for re-skinning.

## Semantic domains

The main semantic domains (see the token table below for the complete grouping):

| Domain | Typical tokens | Purpose |
| --- | --- | --- |
| Primary | `--lh-primary-color` / `-hover` / `-active` / `-bg` / `-border` | The five-piece brand primary set |
| Text | `--lh-text-primary` / `-secondary` / `-tertiary` / `-disabled` | Four-level text hierarchy |
| Background | `--lh-bg-color` / `-page` / `-secondary` / `-overlay` | Page / container / overlay |
| Border | `--lh-border-color` / `-light` / `-dark` | Strokes |
| Status | `--lh-success-color` / `-warning` / `-error` / `-danger` / `-info` | Five semantic colors |
| Radius | `--lh-radius-small` / `-base` / `-large` / `-circle` | Four radius steps |
| Spacing | `--lh-spacing-*` | 8px-based scale |
| Font size | `--lh-font-size-*` | Font-size ramp |
| Shadow | `--lh-shadow-*` | Shadow elevation |
| Animation | `--lh-animation-duration-*` / `-timing-function` | Transition pacing |
| Decoration | `--lh-decoration-color` | Traditional Chinese decoration color |

## Overriding tokens

### At runtime (recommended)

```ts
// ConfigProvider's themeVars (shorthand keys get the --lh- prefix auto-completed)
<lh-config-provider :theme-vars="{ 'primary-color': '#1677ff' }">
```

Or write CSS at your application entry:

```css
:root {
  --lh-primary-color: #1677ff;
  --lh-primary-color-hover: #4096ff;
  --lh-primary-color-active: #0958d9;
}
```

See [Runtime Customization](/theme/customization).

### At compile time (SCSS variables)

```scss
// Your project entry scss, override before @use
$lh-primary-color: #1677ff;

@use '@lh-ui/share/styles';
```

`!default` means "do not override if a value already exists", so assigning before `@use` is enough. **Note**: this only affects the compile-time-baked part; the runtime CSS variables still need to be overridden separately.

## Known token gaps

The "control-height token initiative" has landed (adding `--lh-control-height-mini/small/medium/large/x-large`,
with button / select / input-number / cascader / tree-select / date-picker / time-picker /
input all switched to the tokens, input changing from padding-derived to fixed height, and the
asymmetric `padding-top: 16px` for has-label, the fixed checkbox-check offset, and the duplicated
`translate(-50%,-50%)` hardcoding in switch all fixed along the way). What remains:

1. Inconsistent size steps between spinner and icon (small 16 vs 14, medium 24 vs 16, etc.). Changing either side ripples across the whole library (message / notification / loading / every icon). Trigger condition: visual complaints about mixing LhIcon / LhSpinner in the same slot; at that point it gets its own project.
2. Misaligned size steps: select / switch only have 3 steps, date / time-picker validators are narrowed, tree-select / rate / segmented / pagination have no size, and mini and x-large are barely drawn in the CSS layer (only avatar in the whole library has x-large). This is an API-layer change, decoupled from the height tokens.

## Notes

- **Components must not declare `--lh-*` on their own**: they may only consume via `var(--lh-*, fallback)` (a red line in the root AGENTS.md). New tokens go in `var.scss`.
- **The fallback is mandatory**: `var(--lh-primary-color, #1677ff)` — if a token is missing there is still an acceptable default; `verify:styles` item 2 (var fallback) enforces this.
- **Dark completeness**: when adding a token, ask "should this flip in dark mode?" If yes, add the override in `var-dark.scss`; `verify:styles` item 7 enforces this.
- **Tokens whose value looks like `#{$lh-foo}` are baked at compile time**: they do not flip automatically in dark mode and must be explicitly re-pointed (see [Dark Mode](/theme/dark-mode#the-compile-time-baking-trap)).
