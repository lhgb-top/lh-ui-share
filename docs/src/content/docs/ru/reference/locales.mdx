Интернационализация в семействе lh-ui — это **чистый генератор событий**: `lhlocale` не несёт никакой реактивности фреймворка, а адаптеры UI-библиотек превращают его номер версии `version` в сигнал перерендера своего фреймворка. Так один языковой пакет может одновременно обслуживать Vue3 / Vue2 / React / uniapp, а слой core не зависит ни от одного фреймворка.

## Синглтон и импорт

```ts
import { lhlocale, zhCN, enUS, formatMessage } from '@lh-ui/share/locales'
import type { LhLocalePath, LhLocaleType, LhLocaleMessages } from '@lh-ui/share/locales'
```

## Таблица членов

| Член | Сигнатура | Назначение |
| --- | --- | --- |
| `version` | `get version(): number` | Номер версии: увеличивается при любом изменении языка (адаптер UI подписывается на него и запускает перерендер) |
| `subscribe` | `(listener: LhLocaleListener) => () => void` | Подписка на изменения языка; возвращает функцию отписки |
| `use` | `(options: { locale: LhLocaleType; messages: LhLocaleMessages }) => void` | Регистрирует язык и переключается на него |
| `t` | `(path: LhLocalePath, fallbackOrParams?) => string` | Получает переведённый текст по пути |
| `tm` | `(path: string, fallback?: string[]) => string[]` | Получает тексты в виде массива (названия месяцев / дней недели) |
| `getLocale` | `() => LhLocaleType` | Возвращает текущий язык |
| `setLocale` | `(locale: LhLocaleType) => void` | Переключает текущий язык |
| `add` | `(locale: string, messages: LhLocaleMessages) => void` | Добавляет пользовательский языковой пакет (глубокое слияние) |

## Подробности поведения методов

### t —— автодополнение литеральных ключей

```ts
const t = lhlocale.t   // свойство-стрелочная функция: при деструктуризации this не теряется

t('pagination.total')                       // '共 {total} 条'
t('pagination.total', { total: 42 })        // '共 42 条'
t('not.exists', 'резервный текст')         // 'резервный текст'
t('not.exists')                             // 'not.exists' (возврат к самому пути)
```

Тип `path` — `LhLocalePath`: объединение **всех строковых путей до листьев**, выведенное из структуры `as const` языкового пакета `zh-CN` (например, `'input.placeholder'`). При опечатке в имени ключа редактор сообщит об ошибке. Динамическое построение пути (`t(\`pagination.\${key}\`)`) уходит в перегрузку послабее, где тип сужается до `string`.

Второй параметр принимает две формы: **строка** — fallback-значение; **объект** — параметры интерполяции `{key}` (под капотом — [formatMessage](/ru/core/format)).

### tm —— тексты в виде массива

```ts
lhlocale.tm('datepicker.months')
// ['1月', '2月', …, '12月']

lhlocale.tm('datepicker.weeks')   // ← неверно: weeks — объект, а не массив
lhlocale.tm('datepicker.weeks.sun', ['日'])   // ← тоже неверно: до строковых листьев объекта добирается только t()
```

`t()` возвращает только строки; доступ к листам-массивам (`months`) осуществляется через `tm()`. При промахе или не-массиве возвращается `fallback` (по умолчанию `[]`).

### use против add —— два легко путаемых метода

| | `use` | `add` |
| --- | --- | --- |
| Действие | Регистрирует **и переключается** | Только регистрирует (рассылка происходит лишь при переключении на этот язык) |
| Хранение messages | Записывается в пользовательский реестр `userLocales`, **не перезаписывает встроенный реестр** | То же |
| Способ слияния | Устанавливается весь пакет | **Глубокое слияние** с «текущим активным пакетом» |

Почему `add` делает глубокое слияние: на стороне бизнеса обычно хотят изменить лишь несколько ключей (заменить «确认» на «提交»), а остальные ключи должны остаться доступными из встроенного пакета. Прежняя реализация заменяла пакет целиком, и забытые при передаче ключи просто исчезали.

Почему `use` не перезаписывает встроенный реестр: прежняя реализация `locales[locale] = messages` **навсегда уничтожала встроенный языковой пакет** (вернуться через последующий `setLocale` было уже нельзя). Теперь встроенные пакеты доступны только для чтения, а пользовательские имеют приоритет.

### Семантика «без рассинхронизации» в setLocale

```ts
lhlocale.setLocale('en-US')   // языковой пакет не был зарегистрирован
lhlocale.getLocale()          // 'en-US'  ← сообщается запрошенный язык
lhlocale.t('pagination.total')// текст из встроенного пакета по умолчанию, а не из en-US
```

Выглядит противоречием, но это сделано осознанно: порядок разрешения — `userLocales ?? встроенный locales ?? пакет по умолчанию`. При отсутствии регистрации `getLocale()` сообщает запрошенный язык, а `t()` берёт содержимое пакета по умолчанию — **оба значения не рассинхронизируются** (не возникает странного сочетания «сообщается английский, а текст — китайский»), и сторона бизнеса понимает, что нужно вызвать `add` или `use`.

### version и subscribe

```ts
const unsubscribe = lhlocale.subscribe((version: number) => {
  // язык изменился — запускаем перерендер
})
unsubscribe()   // вызывается при размонтировании компонента
```

`subscribe` возвращает функцию отписки (стиль RxJS). Внутренний `bump()` через try/catch изолирует плохих подписчиков и выводит `[lhlocale] listener error:` — если слушатель одного компонента выбросит исключение, другие компоненты это не затронет.

## Как каждая платформа подписывается на version

```ts
// Vue3 / Vue2 / uniapp
const version = ref(lhlocale.version)
lhlocale.subscribe(() => (version.value = lhlocale.version))
// В шаблоне зависим от version: при изменении происходит перерендер

// React
useSyncExternalStore(lhlocale.subscribe, () => lhlocale.version)
```

## Добавление нового языка

Три шага (те же инструкции — в `src/locales/lang/README.md`):

1. Создать `src/locales/lang/<lang>.ts`, экспортирующий структуру `LhLocaleMessages` (ключи верхнего уровня должны быть выровнены по 38 штук; проверить можно через `satisfies`).
2. Добавить константу в `LH_LANGUAGE_CONST` в `src/constants/index.ts`.
3. Смонтировать файл во встроенном реестре `locales` в `src/locales/locale.ts`.

Затем запустить `pnpm test` (в `theme.spec` и кейсах, связанных с locale, есть регрессия структурной согласованности).

## Связанные типы

| Тип | Определение | Назначение |
| --- | --- | --- |
| `LhLocaleType` | Выводится из `LH_LANGUAGE_CONST` | Объединение поддерживаемых кодов языков |
| `LhLocaleMessages` | `Record<string, LhLocaleMessageValue>` | Тип языкового пакета целиком |
| `LhLocaleMessageValue` | `string \| readonly LhLocaleMessageValue[] \| { readonly [key: string]: LhLocaleMessageValue }` | Листовые узлы языкового пакета (рекурсивно только для чтения) |
| `LhLeaves<T>` | Рекурсивный вывод | Объединение точечных путей всех строковых листьев, выводимое из структуры языкового пакета |
| `LhLocalePath` | `LhLeaves<typeof zhCN>` | Тип литерального ключа для `t()` |
| `LhTranslate` | Тип с перегрузками | Сигнатура вызова `t()` |
| `LhTranslateArray` | `(path: string, fallback?: string[]) => string[]` | Сигнатура вызова `tm()` |
| `LhLocaleListener` | `(version: number) => void` | Слушатель изменения языка |
| `LhLocaleOptions` | `{ locale: LhLocaleType; messages: LhLocaleMessages }` | Аргумент `use()` |

## Примечания

- **`LhLeaves` возвращает `never` для ключей-массивов**: `datepicker.months` — массив, он не адресуется по ключам, и точечный путь `t()` по нему не попадёт — для массивов всегда используется `tm()`.
- **`t` можно деструктурировать**: это свойство-стрелочная функция, поэтому `const t = lhlocale.t` не теряет this.
- **Компоненты core не вызывают `lhlocale` напрямую**: rate / pagination обрабатывают интерполяцию через [formatMessage](/ru/core/format), а поиск текстовых ключей по-прежнему выполняется на стороне UI — core не зависит от побочных эффектов синглтона.
- **`add` делает глубокое слияние**: перекрываются только переданные вами ключи, остальные сохраняются.
