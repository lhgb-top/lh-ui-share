Каталог `styles/` — **единственный источник** BEM-стиилей компонентов для всего семейства ([красная линия 2](/ru/development/contribution#шесть-красных-линий)): 58 каталогов компонентов + слой токенов `theme/common/`. Ни одна UI-библиотека не имеет права копировать стили к себе и править их.

## Структура каталога

```
styles/
├── index.scss                  # Полная агрегация (токены + все компоненты), подключается одной строкой
├── theme/
│   ├── common/
│   │   ├── var.scss            # Светлые токены (:root, 185 CSS-переменных)
│   │   ├── var-dark.scss       # Тёмное переопределение ([data-theme='dark'], .dark, 118 записей)
│   │   ├── variables.scss      # Слой SCSS-переменных (183 переменные $lh-*, константы этапа компиляции)
│   │   ├── patterns.scss       # Система узоров в китайском стиле (6 текстур)
│   │   ├── transition.scss     # Единый источник переходных классов (3 mixin-а)
│   │   └── …                   # Общий слой mixin / function
│   └── index.scss              # Вход агрегации темы
├── button/index.scss           # Стили компонентов (58 каталогов)
├── dialog/index.scss
└── …
```

**Каждый каталог компонента — это один `index.scss`**, импортируемый как `@lh-ui/share/styles/<name>` (vite разрешает каталог в index).

## Способ подключения

```ts
// Четыре способа (подробнее — в разделе «Начало работы»)
import '@lh-ui/share/styles/button'        // Один компонент
import '@lh-ui/share/styles'                // Полностью (styles/index.scss)
import '@lh-ui/share/styles/theme'          // Только токены темы
import '@lh-ui/share/styles/theme/common/var-dark'  // Вплоть до конкретного файла
```

Стратегии инъекции у UI-библиотек разные: plus инъектирует полный объём во входном файле библиотеки, во vue2 стили подключает пользователь по требованию (см. [Стратегии инъекции стилей](/ru/guide/injection)).

## Соглашения BEM

Имена классов всегда имеют префикс `lh-` и строятся по трём уровням BEM:

```scss
.lh-button {                    // Block
  &__text { }                   // Element
  &--primary { }                // Modifier
  &__text--disabled { }         // Element + Modifier
  &.is-loading { }              // Класс состояния (префикс is-, без пространства имён)
}
```

- Имена генерируются [createNamespace](/ru/reference/utils#createnamespace--пространство-имён-bem), что гарантирует единообразие по всему семейству.
- **Классы состояний используют префикс `is-`** (`is-loading` / `is-disabled` / `is-open`) и не являются BEM-модификаторами.
- При добавлении новых классов нужно синхронно обновлять `docs/src/data/classes.json` (генерируется сканированием `styles/*/index.scss` скриптом `scripts/gen-docs-data.mjs`).

## Три слоя токенов

| Слой | Файл | Количество | Особенность |
| --- | --- | --- | --- |
| CSS-переменные (светлые) | `var.scss` | 185 записей | `:root { --lh-*: ... }`, можно переопределять в runtime |
| CSS-переменные (тёмные) | `var-dark.scss` | 118 записей | `[data-theme='dark'], .dark { ... }` переопределяет светлые |
| SCSS-переменные | `variables.scss` | 183 штуки | `$lh-*`, **запекаются на этапе компиляции** |

### Компоненты могут только потреблять CSS-переменные

```scss
// ✅ Правильно: цепочечный fallback через var(), вычисляется в runtime
.lh-button--primary {
  color: var(--lh-color-on-primary, #fff);
  background: var(--lh-primary-color, #1677ff);
}

// ❌ Неправильно: прямая ссылка на SCSS-переменную, в тёмной теме не перевернётся
.lh-button--primary {
  background: #{$lh-primary-color};
}
```

### Ловушка запекания на этапе компиляции

Токены в `var.scss`, значение которых имеет вид `#{$lh-foo}`, на **этапе компиляции заменяются конкретным светлым значением** и в тёмной теме автоматически не переворачиваются. Такие токены должны явно повторно указывать на тёмные семантические токены в `var-dark.scss`:

```scss
// var-dark.scss
[data-theme='dark'],
.dark {
  --lh-menu-item-color: var(--lh-text-primary);   // ← явное перенаправление
}
```

Подобные пробелы однажды привели к тому, что в тёмной теме текст меню / таблиц / таймлайна использовал светлые значения и был невидим. Этому посвящён пункт 7 проверки `pnpm verify:styles` (тёмная доступность). Напротив, **цепочечный fallback** в компонентах вида `var(--lh-foo, var(--lh-bar, #x))` **вычисляется в runtime** и безопасен, если хотя бы один токен в цепочке имеет тёмное переопределение — дублировать объявление не нужно. Подробнее см. [Тёмная тема](/ru/theme/dark-mode).

## `styles/index.scss` генерируется

Файл полной агрегации **генерируется по каталогам компонентов** скриптом `scripts/build-styles.mjs`, а его согласованность проверяется `verify:styles` — **не правьте его руками**. Новые каталоги компонентов автоматически покрываются агрегацией.

## Отменённая маркировка hairline

~~Объявления тонких рамок в 1px должны были сопровождаться строчной меткой `/* hairline */`~~ — эта красная линия **отменена** (uniapp v3 напрямую отдаёт px, больше не транслирует rpx, и метка потеряла смысл; см. `docs/bugfix-log.md`, D-02). 65 исторических меток в `styles/` сохранены как обычные комментарии; **для новых рамок в 1px метка больше не нужна**. Структурные рамки (2px / 3px) и раньше не маркировались.

## Примечания

- **Стили меняются только в этом репозитории**: ни одна UI-библиотека не держит копию компонентного scss. Различия переходных классов между платформами собираются [mixin-ами переходов](/ru/reference/transition-mixins).
- **Цвета — только через `var(--lh-*, fallback)`**; новые хардкод-значения цветов не добавляются (это контролируется пунктом var fallback в verify:styles).
- **У нового компонента обязательно должен быть `styles/<name>/index.scss`**, иначе у него не будет стилевых артефактов на одной из платформ (сборочный скрипт пропустит его тихо, без ошибки).
- **Полнота тёмной темы — жёсткое требование**: все компоненты по умолчанию поддерживают и светлую, и тёмную тему; пробелы в тёмной теме пресекаются пунктом 7 verify:styles.
