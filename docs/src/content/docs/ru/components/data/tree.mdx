Дерево — универсальный контейнер иерархических данных: файловые каталоги, организационные структуры, деревья прав доступа, каскадные меню. Его сложность в **управлении состоянием рекурсивной структуры** — разворачивание, отметка галочками, отложенная загрузка — всё это операции над целом поддереве, к тому же нужно обрабатывать циклические ссылки в данных, отключённые узлы и полувыбранное состояние. `core/tree` собирает этот набор алгоритмов в чистых функциях с иммутабельными обновлениями.

## Когда использовать

- Реализация `LhTree` на каждой платформе: просмотр каталогов, распределение прав, отображение организационной структуры, фильтрация по категориям.
- Сценарии, где иерархическим данным нужно разворачивание/сворачивание, отметка галочками (со связью родитель-потомок) и отложенная загрузка.
- **Не следует использовать**: плоские категории не глубже двух уровней (проще взять каскадный селектор или сегментный контроллер); линейные списки (используйте `virtual-list`).

## Замысел

**Рендеринг — это разворачивание в плоский список**: дерево в UI по сути является **списком с уровнями отступа**. `flattenTree` обходит в глубину, разворачивая только поддеревья, указанные в `expandedKeys`, и выдаёт плоский массив (каждый элемент с `level` / `parentKey` / `ancestorKeys`). UI-слой делает `v-for` по одномерному массиву — это намного проще рекурсивных компонентов и естественно совместимо с виртуальной прокруткой.

**Дедупликация по цепочке предков против глобальной**: рекурсивные функции этого модуля как правило используют **seen по цепочке предков** (`ancestors` / `nextSeen` передаются уровень за уровнем), а не глобальный Set. Цена — защита действует только в рамках одного вызова; выигрыш в том, что **законно разделяемое в DAG поддерево не будет ошибочно пропущено**, и нет утечки состояния между вызовами. Обратите внимание: это иной компромисс, чем у `flattenLeafColumns` в `table` (там глобальный seen) — в таблице DAG-шаринг должен испустить колонку ровно один раз (выравнивание числа столбцов), а в дереве DAG-шаринг при разных путях считается каждым путём отдельно.

**Отключённые узлы не входят в знаменатель полного выбора**: `collectCheckableLeafKeys` пропускает отключённые поддеревья — иначе после выделения родителя из-за отсутствующих отключённых потомков узел **навсегда останется в состоянии indeterminate** и никогда не станет полностью выбранным. Это реальный класс UX-багов.

**Незагруженные нелистовые узлы**: когда `isLeaf !== true` и нет `children`, `collectCheckableLeafKeys` возвращает пустой массив, но `toggleCheckKeys` запишет в `checkedKeys` **собственный ключ** такого узла — в сценарии отложенной загрузки пользователь может сначала поставить галочку на узле, у которого ещё не загружены дети, а после загрузки UI-слой сам решает, делать ли каскад.

**`moveTreeFocus` уже @deprecated**: алгоритм навигации сведён к `core/shared/keyboard.getNextListIndex`, эта обёртка сохраняет старую сигнатуру и прежнюю семантику «при недействительном текущем значении откатиться к первому элементу».

| --- | --- | --- | --- |

## Определения типов

```ts
export interface LhTreeNode {
  key: string
  label: string
  children?: LhTreeNode[]
  disabled?: boolean
  isLeaf?: boolean       // если не указано, выводится по children
}

export interface LhFlatTreeNode {
  node: LhTreeNode
  key: string
  level: number                 // с 0
  parentKey: string | null
  ancestorKeys: string[]        // цепочка предков (без самого узла)
  isLeaf: boolean
}

export type LhTreeCheckState = 'checked' | 'indeterminate' | 'unchecked'
```

## Доступность

`getTreeAria` / `getTreeNodeAria` выдают полную семантику шаблона treeview из APG:

```ts
getTreeAria('lh-tree-1')  // { role: 'tree', id: 'lh-tree-1' }

getTreeNodeAria({ level: 2, expanded: true, selected: true, checked: 'indeterminate' })
// { role: 'treeitem', 'aria-level': 2, 'aria-expanded': true,
//   'aria-selected': true, 'aria-checked': 'indeterminate' }

getTreeNodeAria({ level: 1, leaf: true })
// { role: 'treeitem', 'aria-level': 1 }  ← у листового узла aria-expanded не выводится
```

- `aria-level` начинается с 1 (обратите внимание: `level` у `flattenTree` начинается с 0, поэтому при передаче в aria нужно **+1**).
- **У листового узла нет `aria-expanded`** — чтобы избежать бессмысленного `aria-expanded="false"`, это явное требование APG.
- Три значения `aria-checked`: `true` / `false` / `'indeterminate'` (строка).
- Клавиатурное взаимодействие (treeview из APG): ↑/↓ перемещение между видимыми узлами, → разворачивает/входит в дочерний узел, ← сворачивает/возвращается к родителю, Home/End — к первому/последнему, Enter вызывает выбор.
- **Откуда берётся `aria-level` после разворачивания в плоский список**: из `level + 1` функции `flattenTree`, не следует выводить его обратно из глубины отступа в DOM.

## Примеры использования

```ts
import { flattenTree, toggleCheckKeys, getNodeCheckState } from '@lh-ui/share/core/tree'

const tree = [
  { key: '1', label: 'Отдел разработки', children: [
    { key: '1-1', label: 'Группа фронтенда', children: [{ key: '1-1-1', label: 'lh-ui' }] },
    { key: '1-2', label: 'Группа бэкенда' },
  ]},
  { key: '2', label: 'Продуктовый отдел' },
]

flattenTree(tree, ['1'])
// [Отдел разработки(l0), Группа фронтенда(l1), Группа бэкенда(l1), Продуктовый отдел(l0)]
// Обратите внимание: 1-1-1 не появился, потому что '1-1' нет в expandedKeys

flattenTree(tree, ['1', '1-1'])
// [Отдел разработки, Группа фронтенда, lh-ui(l2), Группа бэкенда, Продуктовый отдел]

toggleCheckKeys(tree, [], '1')
// ['1', '1-1', '1-1-1', '1-2'] (каскад выделяет всех потомков, включая сам узел)

toggleCheckKeys(tree, ['1', '1-1', '1-1-1', '1-2'], '1-1-1')
// ['1-2']  — после снятия '1-1-1' каскад возвращается к предкам: '1-1' больше не выбран полностью и удаляется,
// '1' тоже больше не выбран полностью и удаляется (возврат идёт вплоть до корня)

toggleCheckKeys(tree, ['1-1'], '1-2')
// ['1-1', '1-2']  — возврат только по предкам, другие ветви не трогаются

getNodeCheckState(tree[0], ['1', '1-1', '1-1-1', '1-2'])  // 'checked' (все выбираемые листья выбраны)
getNodeCheckState(tree[0], ['1-1-1'])                      // 'indeterminate' (один из двух выбираемых листьев)
getNodeCheckState(tree[0], ['1-1'])                        // 'unchecked' ('1-1' не лист, не учитывается)
getNodeCheckState(tree[0], [])                             // 'unchecked'
```

}

## Замечания

- **`level` начинается с 0, `aria-level` — с 1**: это самое ошибкоопасное место модуля, при привязке `aria-level` обязательно делайте `+1`.
- **Область действия дедупликации по цепочке предков**: защита работает только в рамках одного вызова. Два независимых вызова `findTreeNode` по одному дереву дедуплицируются каждый сам по себе, и разделяемое поддерево будет пройдено дважды — это сделано намеренно (законный DAG-шаринг), а не баг.
- **`checkStrictly` (без связи родитель-потомок)**: `getNodeCheckState` становится двухзначным, `toggleCheckKeys` меняет только собственный ключ и не возвращается к предкам. Часто используется в сценариях распределения прав.
- **Инвариант каскада для отключённых узлов**: возврат к предкам в `toggleCheckKeys` пропускает отключённых родителей — их ключи не переписываются каскадом. Если бизнесу нужно «программно выбрать отключённый родительский узел», управляйте `checkedKeys` напрямую, а не этой функцией.
- **`isLeaf` в приоритете над `children`**: узел с объявленным `isLeaf: true` обрабатывается как лист, даже если у него есть `children` (часто в сценариях отложенной загрузки: объявление листом блокирует разворачивание).
- **Иммутабельность `mergeLoadedChildren`**: возвращает новое дерево и не модифицирует переданные `nodes` — props.data принадлежит использующей стороне, прямое изменение сломает однонаправленный поток данных.
- **Производительность `flattenTree`**: при каждом изменении expandedKeys всё пересчитывается целиком. При глубокой вложенности и большом объёме данных подумайте о memo поддеревьев (UI-слой кэширует по parentKey).
- **Циклические ссылки в данных**: все рекурсивные функции защищены дедупликацией по цепочке предков и не уйдут в бесконечную рекурсию — но **кольцо в самих данных является ошибкой**, дедупликация лишь не даёт упасть.
