Суть компонента изображения — не показ (хватит и `<img>`), а **предпросмотр**: клик для увеличения, масштабирование колесом, вращение, переключение между несколькими картинками. `core/image` ведает пересчётом состояний просмотрщика — шагами масштабирования и ограничением, нормализацией вращения, циклическим переключением списка изображений.

## Когда использовать

- При реализации `LhImage` на каждой платформе: изображения товаров, предпросмотр аватаров, сканы документов, галереи.
- Сценарии, где нужен увеличенный просмотр по клику (масштабирование/вращение/переключение нескольких изображений).
- **Не следует использовать**: чисто декоративные картинки (прямо `<img>` или фоновое изображение — накладные расходы компонента ни к чему); сложная обрезка/редактирование (это задача image-cropper).

## Замысел

**Ограничение с плавающей точкой при масштабировании**: `stepZoom` каждый раз прибавляет `LH_IMAGE_ZOOM_STEP` (0.25), а затем применяет `Math.round(next * 100) / 100` и ограничивает до `[0.25, 4]`. Округление гарантирует, что `zoom` всегда чистое десятичное (0.25 / 0.5 / 0.75 …), а не `1.0000000000000002` — последнее вызовет видимые глазу ступеньки в `scale()`.

**Коррекция отрицательного остатка для вращения**: `(((rotate + 90) % 360) + 360) % 360` — оператор `%` в JS для отрицательных чисел возвращает отрицательное значение (`-90 % 360 === -90`), а внешний `+360) % 360` приводит его к `[0, 360)`. Хотя данная функция только прибавляет +90 и не может уйти в минус, эта коррекция оборонительная (если вызывающий передаст начальное отрицательное значение угла).

**Циклическое переключение в `stepViewerIndex`**: `(index + delta + total) % total` — на первом изображении нажатие «предыдущее» переносит на последнее. При `total <= 0` возвращается 0 (защита от пустого списка).

**Откат в `normalizePreviewList`**: если `previewSrcList` не передан, происходит откат к `[src]` — одиночный предпросмотр и множественный используют одну и ту же логику, просто `total` равен 1, и кнопки переключения скрываются автоматически.

## Таблица функций

| Функция | Сигнатура | Возврат | Назначение |
| --- | --- | --- | --- |
| `getImageClassNames` | `(state: LhImageState) => string[]` | классы | error / previewable |
| `normalizePreviewList` | `(src, previewSrcList?) => string[]` | список | без previewSrcList откат к [src] |
| `stepZoom` | `(zoom, direction: 1 \| -1) => number` | новое масштабирование | шаг + ограничение |
| `stepRotate` | `(rotate: number) => number` | новый угол | +90°, нормализация к [0,360) |
| `stepViewerIndex` | `(index, total, delta) => number` | новый индекс | циклически |
| `getViewerImageStyle` | `(state: LhImageViewerState) => Record<string, string>` | стили | transform |
| `getImageViewerAria` | `(options?: { id?, label? }) => LhAriaAttrs` | пакет aria-атрибутов | семантика dialog |

Константы: `LH_IMAGE_ZOOM_MIN = 0.25`, `LH_IMAGE_ZOOM_MAX = 4`, `LH_IMAGE_ZOOM_STEP = 0.25`.

## Определения типов

```ts
export type LhImageFit = 'contain' | 'cover' | 'fill' | 'none' | 'scale-down'  // нативный object-fit

export interface LhImageState {
  fit: LhImageFit

  preview: boolean    // доступен ли предпросмотр (отвечает ли на клик + маска-подсказка)
}

  zoom: number
  rotate: number
  index: number
  total: number
}

export const LH_IMAGE_ZOOM_MIN = 0.25
export const LH_IMAGE_ZOOM_MAX = 4
export const LH_IMAGE_ZOOM_STEP = 0.25
```

## Доступность

Просмотрщик представляется как **dialog** с объявлением `aria-modal`:

```ts
getImageViewerAria({ id: 'lh-viewer', label: 'Изображение 2 из 5' })
// { role: 'dialog', 'aria-modal': true, id: 'lh-viewer', 'aria-label': 'Изображение 2 из 5' }

getImageViewerAria()
// { role: 'dialog', 'aria-modal': true }
```

- `aria-modal: true` сообщает скринридеру, что фон недоступен — вместе с `core/shared/focus-trap` это образует ловушку фокуса, закрытие по Esc.
- **`label` с порядковым номером очень полезен**: при просмотре нескольких изображений скринридер объявляет «Изображение 2 из 5», и пользователь знает, сколько ещё осталось; для одиночного изображения достаточно «Просмотр изображения».
- У самого эскиза должен быть `alt` (или `role="img" aria-label`) — если изображение не видно, это единственная текстовая информация. Для декоративных — `alt=""`.
- Кнопки тулбара (увеличить/повернуть/предыдущее/следующее) — кнопки с иконками, для них обязателен `aria-label`.
- **Объявление ошибки загрузки**: плейсхолдер в состоянии `error` должен иметь `role="img"` + `aria-label="Не удалось загрузить изображение"`, иначе пользователь скринридера не узнает, что здесь изначально была картинка.

## Примеры использования

```ts
import { stepZoom, stepRotate, stepViewerIndex, normalizePreviewList } from '@lh-ui/share/core/image'

stepZoom(1, 1)      // 1.25
stepZoom(4, 1)      // 4 (на потолке больше не растёт)
stepZoom(0.25, -1)  // 0.25 (на полу больше не убывает)
stepRotate(0)       // 90
stepRotate(270)     // 0 (нормализация к [0, 360))
stepRotate(-90)     // 0 (коррекция отрицательного остатка)
stepViewerIndex(0, 5, -1)   // 4 (циклический переход в конец)
stepViewerIndex(4, 5, 1)    // 0 (циклический переход в начало)
stepViewerIndex(0, 0, 1)    // 0 (пустой список)
normalizePreviewList('a.jpg', ['b.jpg', 'c.jpg'])  // ['b.jpg', 'c.jpg']
normalizePreviewList('a.jpg', undefined)          // ['a.jpg']
normalizePreviewList('a.jpg', [])                 // ['a.jpg'] (пустой массив тоже откатывается)
getViewerImageStyle({ zoom: 1.5, rotate: 90, index: 0, total: 1 })
// { transform: 'scale(1.5) rotate(90deg)' }
```


## Замечания

- **Связь `previewSrcList` и `src`**: `previewSrcList` — список больших изображений для предпросмотра, он может отличаться от `src` эскиза на странице (эскиз — маленькая картинка для экономии трафика, предпросмотр — оригинал). Если не передать, будет откат к `[src]` — и просматривать будут эскиз, который при увеличении может быть размытым.
- **`zoom` на границе больше не меняется**: `stepZoom` ограничивает до [0.25, 4], кнопки можно делать disabled или давать визуальную обратную связь, чтобы не было «нажал и ничего не произошло».
- **Порядок вращения и масштабирования**: `transform: scale(zoom) rotate(rotate)` — сначала масштабирование, потом вращение. При обратном порядке вращение получает смещение от масштабирования (при вращении вокруг центра различие невелико, но при комбинации со смещением оно заметно).
- **Управление фокусом**: при открытии просмотрщика фокус должен переходить в тулбар, а при закрытии — возвращаться на эскиз; это делается через `core/shared/focus-trap`, иначе TAB убежит за страницу.
- **Повторная попытка при `error`**: core не предоставляет функции повтора; UI-слой может изменить `src`, добавив query-параметр (`?t=Date.now()`), чтобы принудить к перезагрузке — но сначала нужно сбросить состояние `error`.
- **Применение `loaded`**: до завершения загрузки можно показывать скелет (`skeleton`) или слабо размытый плейсхолдер (LQIP).
- **Чувствительность к памяти**: при предпросмотре списка больших изображений реально загружаются только те, что рядом с `index` (браузер грузит по необходимости), но не стоит отрисовывать десятки `<img>` за раз — core не контролирует число отрисовок, UI-слой ограничивает сам.
- **Отображение `fit` в uniapp**: пять значений `object-fit` на стороне мини-программ соответствуют разным значениям `<image mode>` (`scale-down` не имеет прямого соответствия, обычно приближается `aspectFit`) — маппинг делает UI-слой.
