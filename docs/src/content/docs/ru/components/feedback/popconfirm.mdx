Удаление, отправка, публикация — подобные действия, которые «трудно отменить», требуют от пользователя повторного подтверждения. `dialog` для этого слишком тяжёл (модальность, перехват фокуса, маска), а `popconfirm` показывает маленькое всплывающее окно прямо на месте: одно предложение и две кнопки, после подтверждения оно сразу исчезает. Это компонент, **интерактивный вес которого находится ровно между tooltip и dialog**.

## Когда использовать

- В каждой платформе реализован `<LhPopconfirm>`: удаление строки, отмена действия, очистка данных, отправка заказа.
- **Лёгкое, локальное, с малым запасом на отмену** повторное подтверждение.
- **Не использовать для**: последствий настолько серьёзных, что требуется полное внимание пользователя (используйте `dialog` — модальная маска принудительно фокусирует); просто передачи информации (используйте `tooltip` / `message`); подтверждений с указанием причины или флажками (используйте `dialog` с формой).

## Замысел дизайна

**Тон по умолчанию — warning, а не info**: `LH_POPCONFIRM_TYPE_DEFAULT = 'warning'` — появление подтверждения почти всегда означает «здесь есть риск», поэтому по умолчанию тон должен быть предостерегающим. info остаётся для чисто информационных подтверждений («Пометить как прочитанное?»), danger — для необратимых действий («После удаления восстановление невозможно»).

**Три тона, три значка**: info → `info`, warning → `warning`, danger → `error` (имя значка error, а не danger — в библиотеке значков принято имя error, это отображение между разными схемами именования). Неизвестный type откатывается к warning.

**`role="alertdialog"`, а не popover-овский `"dialog"`**: alertdialog в ARIA — это «диалог, требующий немедленного ответа» — программы чтения экрана **зачитывают его в приоритете** (прерывающий характер, как у alert, но требуют от пользователя сделать выбор). Это точнее соответствует семантике «жду твоего решения», чем dialog.

**Контракт событий подтверждения/отмены — на UI-слое**: core предоставляет только имена классов, значки, aria и задержки; события `onConfirm` / `onCancel`, тексты кнопок, состояние loading — всё это в UI-слое, поскольку оно касается общения внутри дерева компонентов (emit), а core не касается API фреймворка.

**Задержки следуют за popover**: по умолчанию в `getDefaultDelay` — 200/100, как и в popover — пузырь подтверждения тоже допускает запуск по hover, и указатель должен иметь возможность войти в него.

## Таблица функций

| Функция | Сигнатура | Возвращаемое значение | Назначение |
| --- | --- | --- | --- |
| `getPopconfirmIconName` | `(type: LhPopconfirmType) => string` | имя значка | для неизвестного type откат к warning |
| `getPopconfirmClass` | `(state: { type, placement, popperClass? }) => string[]` | имена классов | тон + позиция |
| `getPopconfirmTriggerAria` | `(visible, popperId?) => LhAriaAttrs` | пакет aria | expanded/controls/haspopup |
| `getPopconfirmPopperAria` | `(id?) => LhAriaAttrs` | пакет aria | role=alertdialog |
| `getDefaultDelay` | `(showAfter?, hideAfter?) => { show, hide }` | задержки | по умолчанию 200 / 100 |
| `canCloseOnEscape` | `(state: { disabled }) => boolean` | разрешено ли | перехват при disabled |

Константы: `LH_POPCONFIRM_TYPE_DEFAULT = 'warning'`, `LH_POPCONFIRM_PLACEMENT_DEFAULT = 'top'`.

## Определения типов

```ts
export type LhPopconfirmType = 'info' | 'warning' | 'danger'
export type LhPopconfirmTrigger = 'click' | 'hover' | 'focus' | 'manual'

export interface LhPopconfirmState {
  type?: LhPopconfirmType
  trigger?: LhPopconfirmTrigger
  placement?: LhPlacement
  visible?: boolean
  disabled?: boolean
  showIcon?: boolean             // по умолчанию true
}
```

## Доступность

```ts
getPopconfirmPopperAria('pc-1')
// { role: 'alertdialog', id: 'pc-1' }
getPopconfirmTriggerAria(true, 'pc-1')
// { 'aria-expanded': true, 'aria-controls': 'pc-1', 'aria-haspopup': 'true' }
```

- **Зачитывание alertdialog**: при обнаружении alertdialog программа чтения экрана немедленно зачитывает его содержимое (aria-labelledby или внутренний текст), **пользователю не нужно читать его самостоятельно** — в этом его большая обязательность по сравнению с dialog, что соответствует намерению «жду подтверждения».
- **У кнопок должен быть ясный текст**: «ОК / Отмена» лучше, чем «OK / NO» или значки-кнопки. При тоне `danger` текст кнопки подтверждения рекомендуется формулировать с указанием последствий («Удалить», а не «ОК»).
- **Отмена — безопасное направление**: что Enter должно запускать по умолчанию — **подтверждение** или **отмену**? Общая практика — помещать начальный фокус на кнопку **«Отмена»** (одно нажатие Tab + Enter — безопасный выход) — для деструктивных операций не стоит заранее помещать фокус на подтверждение. Это решение UI-слоя, core в него не вмешивается.
- **Esc = отмена**: когда `canCloseOnEscape` разрешает, Esc должен запускать onCancel, а не просто закрывать — семантически «закрыть окно подтверждения» означает «не подтверждать».
- **Значок с aria-hidden**: семантический значок (warning/error) уже передан текстом, а сам значок декоративен, чтобы программа чтения не зачитывала дважды «предупреждение».

## Стили и токены

| Имя класса | Семантика |
| --- | --- |
| `.lh-popconfirm__popper` | контейнер пузыря |
| `.lh-popconfirm__popper--{info\|warning\|danger}` | тон (цвет значка + цвет кнопки подтверждения) |
| `.lh-popconfirm__popper--{top\|bottom\|…}` | позиция |
| `.lh-popconfirm__icon` | значок тона |
| `.lh-popconfirm__title` | текст заголовка |
| `.lh-popconfirm__actions` | область кнопок (выравнивание по правому краю) |

Цвет кнопки подтверждения следует тону: danger использует `--lh-danger-color`, warning — `--lh-warning-color`, info — `--lh-primary-color`.

## Замечания

- **Заголовок должен чётко указывать последствия**: «Точно удалить?» — плохой текст (последствие не названо); «После удаления восстановление невозможно. Удалить эту строку?» — хороший. Это основа UX popconfirm.
- **Не вкладывать друг в друга**: popconfirm внутри popconfirm заставит пользователя гадать, какой именно слой он сейчас подтверждает. Для многошаговых подтверждений используйте dialog.
- **Триггер — отключённая кнопка**: кнопка с `disabled` не генерирует события (нативное ограничение), и popconfirm не откроется — бизнес-слой должен обработать это сам (обернуть в неотключённый элемент или вообще не рендерить при отключении).
- **Момент закрытия при асинхронном подтверждении**: во время обработки confirm следует отключить обе кнопки + маску для защиты от повторных нажатий; при ошибке **оставить пузырь открытым** и показать ошибку, а закрывать только при успехе. Синхронное закрытие пузыря прямо внутри onConfirm — частый bug.
- **Сочетание с message**: после завершения подтвердённого действия дайте обратную связь успехом через `message` («Удалено») — это стандартная цепочка «подтверждение → выполнение → обратная связь».
- **Запуск по hover на мобильных**: как и в popover, на сенсорных экранах нет hover. Для межплатформенного использования по умолчанию применяется запуск по click.
- **`role="alertdialog"` не несёт неявной семантики кнопок**: область кнопок должна рендериться настоящими `<button>` (а не div + onclick), иначе пользователи клавиатуры не смогут с ними работать.
