Токен (token) — это переменная языка дизайна: цвет, размер шрифта, отступ, скругление, тень, длительность анимации получают имена в виде CSS-переменных `--lh-*`, а компоненты потребляют только имена и не записывают значения. Смена облика — это смена токенов.

## Три слоя токенов

| Слой | Расположение | Количество | Момент вычисления | Переопределяемость |
| --- | --- | --- | --- | --- |
| CSS-переменные · светлые | `:root` в `styles/theme/common/var.scss` | **185 записей** | runtime | ✅ переопределяются как угодно |
| CSS-переменные · тёмные | `[data-theme='dark'], .dark` в `styles/theme/common/var-dark.scss` | **118 записей** | runtime | ✅ |
| SCSS-переменные | `styles/theme/common/variables.scss` | **183 штуки** | **этап компиляции** | ⚠️ только правка исходников и пересборка |

### Светлые токены (var.scss)

```scss
:root {
  --lh-primary-color: #2B4C7C;
  --lh-text-primary: rgba(0, 0, 0, 0.88);
  --lh-bg-color: #FAF6F0;
  --lh-border-color: #e5e6eb;
  --lh-radius-base: 6px;
  --lh-spacing-base: 8px;
  // ... 185 записей
}
```

### Тёмное переопределение (var-dark.scss)

```scss
[data-theme='dark'],
.dark {
  --lh-bg-color: #2A2520;
  --lh-text-primary: #E8E0D8;
  --lh-border-color: #3A3530;
  // ... 118 записей
}
```

Тёмная тема — это **слой переопределения**, а не отдельный набор: записываются только 118 токенов, которые нужно перевернуть; остальные наследуют светлые значения.

### SCSS-переменные (variables.scss)

```scss
$lh-primary-color: #2B4C7C !default;
$lh-border-radius-base: 6px !default;
// ... 183 штуки
```

Назначение SCSS-переменных — **участие в вычислениях на этапе компиляции**: смешение цветов (`mix()` / `shade()`), компоновка теней (сложение нескольких shadow) — то, чего CSS-переменные не умеют. Плата за это — **запекание на этапе компиляции**, в тёмной теме они автоматически не переворачиваются.

## Многоуровневая структура токенов

Токены разделены на три уровня: первые два — в файлах глобальной темы, третий — в собственных стилях каждого компонента:

```scss
// 1. SCSS-переменные (variables.scss, этап компиляции)
$lh-primary: #2B4C7C !default;
$lh-text-primary: #2C2C2C !default;

// 2. Глобальные CSS-переменные (:root в var.scss, 190 записей)
--lh-primary-color: #{$lh-primary};
--lh-text-primary: #{$lh-text-primary};
--lh-bg-color: #FAF6F0;

// 3. Переменные уровня компонентов (собственные scss компонента; область действия — BEM-корень компонента)
.lh-card {
  --lh-card-bg: var(--lh-bg-color, #FAF6F0);
  --lh-card-border-radius: calc(var(--lh-border-radius-base, 2px) + 2px);
}
```

Ключевые механизмы:

- **Между 1-м и 2-м уровнями — интерполяция на этапе компиляции, а не цепочка ссылок var()**: значение `--lh-primary-color` в сборку входит из `$lh-primary`; изменить SCSS-переменную в runtime невозможно (нужна пересборка). Промежуточного слоя «базовая палитра» в проекте **нет** — переменных вроде `--lh-blue-6` для оттенков цвета не существует, семантические токены генерируются напрямую из SCSS-переменных.
- **Две точки опоры для смены облика**: изменить SCSS-переменные в `variables.scss` и пересобрать (влияет на все семантические токены) или переопределить CSS-переменные на `:root` в runtime (этим путём идёт `themeVars` у ConfigProvider, действует мгновенно).
- **3-й уровень по умолчанию ссылается на 2-й**: значения переменных уровня компонента по умолчанию представляют собой ссылки `var()` на глобальные токены (с fallback) — это и сохраняет связь с темой, и позволяет через themeVars точечно переопределить отдельный компонент.

## Переопределение токенов

### В runtime (рекомендуется)

```ts
// themeVars у ConfigProvider (префикс --lh- добавляется к сокращённым ключам автоматически)
<lh-config-provider :theme-vars="{ 'primary-color': '#1677ff' }">
```

Или записать CSS во входном файле приложения:

```css
:root {
  --lh-primary-color: #1677ff;
  --lh-primary-color-hover: #4096ff;
  --lh-primary-color-active: #0958d9;
}
```

Подробнее см. [Настройка в runtime](/ru/theme/customization).

### На этапе компиляции (SCSS-переменные)

```scss
// Входной scss проекта; переопределение до @use
$lh-primary-color: #1677ff;

@use '@lh-ui/share/styles';
```

Семантика `!default` — «не перекрывать, если значение уже есть», поэтому присвоения перед `@use` достаточно. **Важно**: это влияет только на ту часть, которая запекается на этапе компиляции; CSS-переменные в runtime нужно переопределять отдельно.

## Известные пробелы в токенах

«Специальный выпуск по токенам высоты» состоялся (добавлены `--lh-control-height-mini/small/medium/large/x-large`;
button / select / input-number / cascader / tree-select / date-picker / time-picker /
input переведены на токены; input вместо производной от padding получил фиксированную высоту, асимметричный
`padding-top: 16px` для наличия метки, фиксированное смещение галочки checkbox и повторяющийся
хардкод `translate(-50%,-50%)` в switch исправлены). Что ещё предстоит обработать:

1. Размерные шаги spinner и icon с одинаковыми именами не совпадают (small 16 vs 14, medium 24 vs 16 и т. д.). Изменение любой стороны затронет всю библиотеку (message / notification / loading / все иконки); условие для запуска: жалобы на визуальные расхождения там, где в одном слоте смешиваются LhIcon / LhSpinner — тогда это выделяется в отдельный проект.
2. Размерные шаги выровнены не везде: select / switch имеют всего 3 шага, валидатор в date / time-picker сужен, у tree-select / rate / segmented / pagination нет size, а mini и x-large на уровне CSS почти не нарисованы (x-large есть только у avatar по всей библиотеке). Это изменения на уровне API, не связанные с токенами высоты.

## Примечания

- **Компонентам запрещено самостоятельно объявлять `--lh-*`**: они могут только потреблять токены через `var(--lh-*, fallback)` (красная линия из корневого AGENTS.md). Новые токены добавляются в `var.scss`.
- **fallback обязателен**: `var(--lh-primary-color, #1677ff)` — при отсутствии токена остаётся приемлемое значение по умолчанию; это контролируется пунктом 2 verify:styles (var fallback).
- **Полнота тёмной темы**: добавляя токен, спросите «должен ли он перевернуться в тёмной теме», и если да — добавьте переопределение в `var-dark.scss`; это контролируется пунктом 7 verify:styles.
- **Токены со значением вида `#{$lh-foo}` запекаются на этапе компиляции**: в тёмной теме они автоматически не переворачиваются и требуют явного перенаправления (см. [Тёмная тема](/ru/theme/dark-mode#ловушка-запекания-на-этапе-компиляции)).
