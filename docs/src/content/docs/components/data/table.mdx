表格是数据展示的「重器」：排序、筛选、多级表头、固定列、虚拟滚动、列宽拖拽，每一项都是独立的算法难题。`core/table` 把这些全部抽成纯函数——UI 层只管把结果绑到 DOM。它是本包里函数最多的组件模块之一。

## 何时使用

- 各端实现 `LhTable`：后台列表、数据报表、批量操作表格。
- 结构化数据需要排序 / 筛选 / 固定列 / 多级表头的场景。
- **不该用它**：数据量极小且无交互（简单的 `descriptions` 或手写表格更轻）；卡片式信息流（用 `card` 布局）。

## 设计意图

**空值排末尾**：`sortTableRows` 对 `null` / `undefined` / `NaN` 统一处理——它们不参与正常比较，一律排到末尾，**且 desc 时仍在末尾**。这是一个明确的产品决策：空数据的行不应该因为倒序就跑到第一行挡住有效数据。

**多级表头的 DAG 安全**：`flattenLeafColumns` 与 `buildHeaderCells` 用**全局 seen** 而非祖先链 seen——因为同一 column 对象可能被 DAG 式共享引用（同一列出现在两个组下），全局判重保证它只发射一次，表体列数才与表头叶子格数一致。`buildHeaderCells` 的 `leafSpan` 用「递归实际发射的叶子数」而非先验计数，正是为了防止共享子树被算两遍导致列数错位。

**组表头的 sticky 继承**：`getHeaderStickyOffsets` 只在「区间内叶子列全部 fixed 同侧」时让组表头继承首末叶子的偏移——跨固定区与流动区的组表头无法用单一偏移定位，干脆不固定。

**`clampColumnWidth` 的同构重载**：`数进数出、字符串进字符串出`，调用方不必为同构变换再做类型断言；NaN 直接返回下限（拖拽过程中可能出现 NaN 坐标）。

**`computeVisibleRange` 已 @deprecated**：虚拟滚动算法已收敛到共享内核 `core/shared/virtual` 的 `computeRange`（与 VirtualList 同源），本函数保留兼容别名供 vue2 等下游既有引用。

## 类型定义

```ts
export type LhTableAlign = 'left' | 'center' | 'right'
export type LhTableSortOrder = 'asc' | 'desc'
export type LhTableRow = Record<string, any>

export interface LhTableColumn {
  prop: string
  label: string
  width?: number | string          // 数字为 px
  align?: LhTableAlign
  fixed?: 'left' | 'right'         // 需配合 width
  sortable?: boolean
  slot?: string                    // 自定义单元格插槽名
  formatter?: (row: LhTableRow, value: any) => string
  children?: LhTableColumn[]       // 配置即得多级表头
  filters?: LhTableFilterOption[]  // 仅叶子列生效
  filterMethod?: (value: string | number, row: LhTableRow) => boolean
  filterMultiple?: boolean         // 默认 true
  resizable?: boolean              // 需为数字 width 的叶子列
}

export interface LhTableHeaderCell {
  column: LhTableColumn
  level: number          // 表头层级 0 起
  leafStart: number      // 叶子列序起点
  leafSpan: number       // 跨叶子列数
  rowspan: number        // 补齐到最大深度
  colspan: number        // = leafSpan
  isLeaf: boolean
}

export interface LhTableVisibleRange { start: number; end: number; offsetY: number; totalHeight: number }
export interface LhTableCellSticky { left?: number; right?: number }
```

## 无障碍

`getTableSortAria` 输出 `aria-sort`，与 `cycleSortOrder` 的状态机严格对齐：

```ts
getTableSortAria({ sortable: true, sortOrder: 'asc' })    // { 'aria-sort': 'ascending' }
getTableSortAria({ sortable: true, sortOrder: 'desc' })   // { 'aria-sort': 'descending' }
getTableSortAria({ sortable: true })                      // { 'aria-sort': 'none' }
getTableSortAria({ sortable: false })                     // {}（不可排序列不输出）
```

注意第三种：未排序时输出 `aria-sort="none"` 而非省略——这是 APG 的明确要求，**显式声明「该列可排序但当前未排序」**，读屏软件据此提示用户可在此列执行排序操作。

其余约定（UI 层实现）：表头用 `<th scope="col">`；固定列不要用 `tabindex` 制造额外焦点；分页区是独立的 `nav`；行选择列的 checkbox 需 `aria-label`（如「选择第 3 行」）。

## 使用示例

```ts
import { cycleSortOrder, sortTableRows, filterTableRows, buildHeaderCells } from '@lh-ui/share/core/table'

cycleSortOrder(undefined)  // 'asc'
cycleSortOrder('asc')      // 'desc'
cycleSortOrder('desc')     // undefined（取消排序）

const rows = [
  { name: '王五', age: 30 },
  { name: '李四', age: null },
  { name: '张三', age: 20 },
]
sortTableRows(rows, 'age', 'asc')
// 张三 20 → 王五 30 → 李四 null（空值恒在末尾）
sortTableRows(rows, 'age', 'desc')
// 王五 30 → 张三 20 → 李四 null（倒序时空值仍在末尾）
sortTableRows(rows, 'age', undefined)  // 原顺序副本

filterTableRows(rows, [{ column: { prop: 'name' }, values: ['张三'] }])
// [{ name: '张三', age: 20 }]
filterTableRows(rows, [])  // 全量副本（无激活筛选）

// 多级表头
const columns = [
  { label: '基本信息', children: [{ prop: 'name', label: '姓名' }, { prop: 'age', label: '年龄' }] },
  { prop: 'city', label: '城市' },
]
flattenLeafColumns(columns)  // [姓名, 年龄, 城市]（表体按此渲染）
buildHeaderCells(columns)
// 基本信息（level 0, leafStart 0, colspan 2）、姓名（rowspan 2 补齐）、
// 年龄（rowspan 2）、城市（level 0, rowspan 2）
```

## 注意事项

- **行高一致性是虚拟滚动的前提**：`computeRange` 假定每行等高；若行内内容撑高（长文本换行），虚拟滚动会错位——高度不规则的表格不要开 `virtual`。
- **固定列必须声明 `width`**：`getStickyOffsets` 只对数字 px 或 `'Npx'` 字符串换算偏移；`'20%'` 这类单位无法换算，按 0 累加，固定列会叠在一起。
- **`resizable` 的前提**：必须是**数字 width 的叶子列**，拖宽后用 `clampColumnWidth` 钳到下限再写回列配置。
- **排序的 `prop` 与数据的键**：`sortTableRows` 按 `row[prop]` 取值，嵌套字段（`user.name`）不自动支持，用 `sorter` 自定义。
- **筛选的列内 OR**：同一列的多个选中值是「或」关系，不同列之间是「与」——这是与 Element 一致的通行的语义。
- **多级表头的表体列序**：表体必须用 `flattenLeafColumns(columns)` 而非 `columns`，否则列数与表头叶子格数不匹配。
- **DAG 共享列**：同一 column 对象在两组下引用时，全局 seen 保证只发射一次——但**引用同一个对象的副作用是改一处即改两处**，若需要「同名不同配置」请深拷贝。
- **大数据量的排序是 O(n log n)**：每帧排序上万行会卡顿，考虑服务端排序（`sortable: 'custom'` 由 UI 层约定）。
- **`getTableSortAria` 的 `aria-sort` 挂在 `<th>` 上**，不是整列的每个单元格。
