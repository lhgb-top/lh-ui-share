下拉选择器是「触发器 + 浮层列表」模式的最简实现。`core/select` 管选项查找、确定性 option id 生成、以及 APG combobox 模式的三层无障碍属性包。**定位计算不在这里**——浮层的坐标由 `core/shared/popper` 负责（见 [popper](/core/popper)）。

## 何时使用

- 各端实现 `LhSelect`。
- 单选场景；多选用级联或 checkbox-group。
- **不该用它**：选项需要树形层级（用 `cascader`）、选项超过几百个（考虑 `virtual-list` 虚拟化）。

```ts
import {

} from '@lh-ui/share/core/select'
import type { LhSelectOption, LhSelectState } from '@lh-ui/share/core/select'
```

## 设计意图

`getSelectOptionId(listboxId, index)` 的「确定性」是 APG combobox 模式能工作的前提：触发器用 `aria-activedescendant` 引用当前高亮项，两者必须指向**同一个 DOM id**。与其让 UI 层随手生成 id 再想办法同步，不如在 core 层规定 `${listboxId}-option-${index}`，两端都按这个规则取值。

它的守卫同样重要：`listboxId` 为空、index 非整数、或 `index < 0`（-1 表示无高亮）时返回 **undefined**——undefined 的属性会被框架 v-bind 忽略，不会产生指向不存在元素的 `aria-activedescendant`。

## 函数表

| 函数 | 签名 | 返回 | 作用 |
| --- | --- | --- | --- |
| `findSelectOption` | `(options: LhSelectOption[], value: unknown) => LhSelectOption \| undefined` | 选项 | 用 `Object.is` 精确匹配 value |
| `getNextEnabledIndex` | `(options: LhSelectOption[], currentIndex: number, direction: 1 \| -1) => number` | 下标 | **@deprecated**，转调 `shared/keyboard.getNextListIndex` |
| `getSelectOptionId` | `(listboxId: string \| undefined, index: number) => string \| undefined` | id | 确定性拼接，非法输入返回 undefined |
| `getSelectTriggerAria` | `(options: { visible: boolean; listboxId?: string; highlightedIndex: number }) => LhAriaAttrs` | aria 属性包 | combobox 触发器 |
| `getSelectListboxAria` | `(id?: string) => LhAriaAttrs` | aria 属性包 | listbox 容器 |
| `getSelectOptionAria` | `(options: { listboxId?: string; index: number; selected: boolean; disabled?: boolean }) => LhAriaAttrs` | aria 属性包 | 单个选项 |

## 无障碍

三层属性包构成完整的 combobox 模式：

```ts
// 触发器：aria-haspopup="listbox" + aria-expanded + aria-controls
getSelectTriggerAria({ visible: true, listboxId: 'my-listbox', highlightedIndex: 2 })
// { role: 'combobox', 'aria-expanded': true, 'aria-controls': 'my-listbox',
//   'aria-haspopup': 'listbox', 'aria-activedescendant': 'my-listbox-option-2' }

// 浮层：role="listbox" + id（与触发器 aria-controls 对应）
getSelectListboxAria('my-listbox')  // { role: 'listbox', id: 'my-listbox' }

// 选项：role="option" + id + aria-selected
getSelectOptionAria({ listboxId: 'my-listbox', index: 2, selected: true })
// { role: 'option', id: 'my-listbox-option-2', 'aria-selected': true }
```

键盘交互的完整闭环（UI 层实施，core 提供算法）：ArrowDown/Up 移动 `highlightedIndex`（用 `shared/keyboard.getNextListIndex`，首尾循环、跳过 disabled），Enter 选中，Esc 关闭。**视觉高亮必须与 `highlightedIndex` 同源**，否则会出现「aria 指向 A、眼睛看到 B」。

## 使用示例

```ts
import { findSelectOption, getSelectOptionId, getSelectTriggerAria } from '@lh-ui/share/core/select'

const options = [
  { label: '青花瓷', value: 'cerblue' },
  { label: '水墨', value: 'shuimo', disabled: true },
]
findSelectOption(options, 'cerblue')   // { label: '青花瓷', value: 'cerblue' }
findSelectOption(options, 'nope')      // undefined
getSelectOptionId('lb', 0)             // 'lb-option-0'
getSelectOptionId('lb', -1)            // undefined（无高亮）
getSelectOptionId(undefined, 0)        // undefined
```

<!-- Vue3 -->

## 注意事项

- **`Object.is` 而非 `===`**：`findSelectOption` 用 `Object.is`，能正确处理 `NaN` 与 `-0` 这类边界（虽然实际选项值很少用到）。
- **`getNextEnabledIndex` 已废弃**：实现已收敛到 `shared/keyboard.getNextListIndex`，本函数仅转调，保留旧签名。新代码直接引内核。
- **id 稳定性**：`listboxId` 在组件生命周期内不能变（否则 `aria-activedescendant` 指向旧 id），用各端的稳定 id 生成。
- **传送门（teleport）**：浮层传送到 body 时，`aria-controls` 仍然有效（同文档内），但**焦点管理**要小心——选项点击后焦点应回到触发器。
