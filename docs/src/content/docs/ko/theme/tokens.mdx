토큰(token)은 디자인 언어의 변수화입니다: 색, 글자 크기, 간격, 모서리 둥글기, 섀도, 애니메이션 지속 시간이 모두 `--lh-*`라는 CSS 변수로 명명되고, 컴포넌트는 이름만 소비하고 값을 쓰지 않습니다. 스킨을 바꾼다는 것은 토큰을 바꾸는 것입니다.

## 3계층 토큰

| 계층 | 위치 | 수량 | 평가 시점 | 덮어쓰기 가능성 |
| --- | --- | --- | --- | --- |
| CSS 변수 · 밝은색 | `styles/theme/common/var.scss`의 `:root` | **185개** | 런타임 | ✅ 자유롭게 덮어쓰기 |
| CSS 변수 · 어두운색 | `styles/theme/common/var-dark.scss`의 `[data-theme='dark'], .dark` | **118개** | 런타임 | ✅ |
| SCSS 변수 | `styles/theme/common/variables.scss` | **183개** | **컴파일 타임** | ⚠️ 소스를 고쳐 재컴파일만 가능 |

### 밝은색 토큰(var.scss)

```scss
:root {
  --lh-primary-color: #2B4C7C;
  --lh-text-primary: rgba(0, 0, 0, 0.88);
  --lh-bg-color: #FAF6F0;
  --lh-border-color: #e5e6eb;
  --lh-radius-base: 6px;
  --lh-spacing-base: 8px;
  // ... 185개
}
```

### 어두운색 덮어쓰기(var-dark.scss)

```scss
[data-theme='dark'],
.dark {
  --lh-bg-color: #2A2520;
  --lh-text-primary: #E8E0D8;
  --lh-border-color: #3A3530;
  // ... 118개
}
```

어두운색은 별도의 한 벌이 아니라 **덮어쓰기 계층**입니다: 전환이 필요한 118개만 쓰고, 나머지는 밝은색 값을 따릅니다.

### SCSS 변수(variables.scss)

```scss
$lh-primary-color: #2B4C7C !default;
$lh-border-radius-base: 6px !default;
// ... 183개
```

SCSS 변수의 용도는 **컴파일 타임 계산에 참여**하는 것입니다: 색 혼합(`mix()` / `shade()`), 섀도 합성(여러 층의 shadow를 더하는 것) 같은, CSS 변수로는 할 수 없는 일들입니다. 그 대가가 **컴파일 타임에 구워진다**는 것입니다 —— 어두운색에서 자동으로 전환되지 않습니다.

## 토큰의 계층 구조

토큰은 세 단계로 나뉘며, 앞의 두 단계는 전역 테마 파일에, 세 번째 단계는 각 컴포넌트 자신의 스타일에 있습니다:

```scss
// 1. SCSS 변수(variables.scss, 컴파일 타임)
$lh-primary: #2B4C7C !default;
$lh-text-primary: #2C2C2C !default;

// 2. 전역 CSS 변수(var.scss의 :root, 190개)
--lh-primary-color: #{$lh-primary};
--lh-text-primary: #{$lh-text-primary};
--lh-bg-color: #FAF6F0;

// 3. 컴포넌트 수준 변수(컴포넌트 자신의 scss, 유효 범위는 컴포넌트의 BEM 루트)
.lh-card {
  --lh-card-bg: var(--lh-bg-color, #FAF6F0);
  --lh-card-border-radius: calc(var(--lh-border-radius-base, 2px) + 2px);
}
```

핵심 메커니즘:

- **1, 2단계 사이는 컴파일 타임 보간이지 var() 참조 사슬이 아닙니다**: `--lh-primary-color`의 값은 빌드 시에 `$lh-primary`에서 구워 들어오며, 런타임에 SCSS 변수를 바꾸는 것은 효과가 없습니다(재컴파일해야 함). 프로젝트에는 **"기본 팔레트" 중간 계층이 없습니다** —— `--lh-blue-6` 같은 색단계 변수는 존재하지 않으며, 의미 토큰이 SCSS 변수에서 직접 생성됩니다.
- **스킨 변경의 두 지렛대**: `variables.scss`의 SCSS 변수를 바꾸어 재컴파일(모든 의미 토큰에 영향), 또는 런타임에 `:root`의 CSS 변수를 덮어쓰기(`ConfigProvider`의 themeVars가 이 길을 감, 즉시 효과).
- **3단계는 기본적으로 2단계를 참조합니다**: 컴포넌트 수준 변수의 기본값은 보통 전역 토큰의 `var()` 참조(폴백 포함)이며, 테마 연동을 유지하면서도 themeVars로 단일 컴포넌트를 목적지로 덮어쓸 수 있습니다.

## 의미 도메인

주요 의미 도메인(전체 그룹은 아래 토큰 표 참고):

| 도메인 | 전형 토큰 | 용도 |
| --- | --- | --- |
| 주색 | `--lh-primary-color` / `-hover` / `-active` / `-bg` / `-border` | 브랜드 주색의 5종 세트 |
| 글자 | `--lh-text-primary` / `-secondary` / `-tertiary` / `-disabled` | 4단계 글자 계층 |
| 배경 | `--lh-bg-color` / `-page` / `-secondary` / `-overlay` | 페이지 / 컨테이너 / 덮개 |
| 테두리 | `--lh-border-color` / `-light` / `-dark` | 외곽선 |
| 상태 | `--lh-success-color` / `-warning` / `-error` / `-danger` / `-info` | 5개의 의미 색 |

| 섀도 | `--lh-shadow-*` | 섀도 계층 |

## 토큰 덮어쓰기

### 런타임(권장)

```ts
// ConfigProvider의 themeVars(약식 키에 자동으로 --lh- 접두사 보충)
<lh-config-provider :theme-vars="{ 'primary-color': '#1677ff' }">
```

또는 애플리케이션 진입점에 CSS로 작성:

```css
:root {
  --lh-primary-color: #1677ff;
  --lh-primary-color-hover: #4096ff;
  --lh-primary-color-active: #0958d9;
}
```

자세한 내용은 [런타임 맞춤 설정](/ko/theme/customization)을 참고하세요.

### 컴파일 타임(SCSS 변수)

```scss
// 프로젝트 진입점 scss, @use 이전에 덮어쓰기
$lh-primary-color: #1677ff;

@use '@lh-ui/share/styles';
```

`!default`의 의미는 "이미 값이 있으면 덮어쓰지 않음"이므로, `@use` 이전에 할당하기만 하면 됩니다. **주의**: 이것은 컴파일 타임에 구워지는 부분에만 영향을 주며, 런타임의 CSS 변수는 따로 덮어써야 합니다.

## 알려진 토큰 갭

"높이 토큰 전문 작업"이 착지했습니다(`--lh-control-height-mini/small/medium/large/x-large`를 새로 만들고,
button / select / input-number / cascader / tree-select / date-picker / time-picker /
input이 모두 이 토큰을 참조하도록 변경, input은 padding에서 파생되던 것을 고정 높이로 바꾸고, has-label의 비대칭
`padding-top: 16px`, checkbox 체크 표시의 고정 오프셋, switch의 `translate(-50%,-50%)` 중복
하드코딩을 함께 수정). 여전히 남아 있는 것:

1. spinner와 icon의 같은 이름 크기 단계가 일치하지 않습니다(small 16 vs 14, medium 24 vs 16 등). 어느 한쪽을 바꾸면 전 라이브러리에 파급됩니다(message / notification / loading / 모든 아이콘). 트리거 조건: 같은 슬롯에 LhIcon / LhSpinner를 섞어 쓸 때의 시각적 불만이 들어올 때, 그때 별도로 착수.
2. size 단계가 고르지 않습니다: select / switch는 3단계만 있고, date / time-picker의 validator는 좁혀져 있으며, tree-select / rate / segmented / pagination에는 size가 없고, mini와 x-large는 CSS 계층에서 거의 그려지지 않았습니다(전 라이브러리에서 x-large가 있는 것은 avatar뿐). API 계층의 변경으로, 높이 토큰과는 분리되어 있습니다.

## 주의 사항

- **컴포넌트가 스스로 `--lh-*`를 선언하는 것은 허용되지 않습니다**: `var(--lh-*, fallback)`로만 소비(루트 AGENTS.md의 레드라인). 새 토큰은 `var.scss`에 추가합니다.
- **폴백은 필수 작성**: `var(--lh-primary-color, #1677ff)` —— 토큰이 없어도 받아들일 수 있는 기본값이 있으며, `verify:styles`의 2번째 항목(var fallback)이 관리합니다.
- **어두운색 완전성**: 새 토큰을 추가할 때 "어두운색에서 전환이 필요한가"를 자문하고, 필요하면 `var-dark.scss`에 덮어쓰기를 보충하며, `verify:styles`의 7번째 항목이 관리합니다.
- **값이 `#{$lh-foo}` 형태인 토큰은 컴파일 타임에 구워진 것**입니다: 어두운색에서 자동으로 전환되지 않으므로 반드시 명시적으로 다시 가리켜야 합니다([다크 모드](/ko/theme/dark-mode#컴파일-타임-베이크-함정) 참고).
